# 从卖方研报到可复用的公募 REITs 投研 Skills：项目复盘、研究发现与下一步

> 面向：指导老师  
> 项目：`Siyezzz/shenwan`  
> 仓库：<https://github.com/Siyezzz/shenwan>  
> 复盘基准：GitHub `main` 分支，2026-11-06 可见版本  
> 核心目标：把公募 REITs 投前、投后研究任务转化为可复用、可追溯、可检验的 AI 研究工作流，并用三个真实案例验证。

## 一、我从以前的 FLOW 和卖方研报中学到了什么

一开始，我以为把一份卖方研报拆成数据需求、分析步骤和输出模板，再让模型照着执行，就能得到一个好用的研究 Skill。实际做下来，我发现这只是把研究员写在报告里的结果和步骤搬进了流程，并没有自动获得研究员真正的判断能力。

对已有 FLOW、Skill 和卖方研报的学习，逐渐暴露出几个容易被忽略的坑。

### 1. 有数据需求，不等于数据真的能拿到

早期研究流程里有大量数据需求，但数据需求与真实数据源之间没有稳定映射。有些指标写得很具体，来源编号却为空；有些数据源看起来存在，实际接口并不能公开访问。

因此，我把“数据需求”与“数据探针”分开：每个关键指标都要说明来源、获取方式、适用期间、是否实际验证，以及获取失败时的替代来源。不能因为 FLOW 写了“读取某指标”，就假设该指标已经拿到。

本项目的一个真实例子是交易所公告接口需要额外的内部参数，公开请求无法直接完成枚举。项目最终使用东方财富基金公告接口获取公告原文 PDF，并在 README 和来源审计中如实说明：这是第三方获取渠道，不是上交所直连。

### 2. “高、中、低”如果没有标尺，只是主观形容

研报中经常出现“出租率处于较高水平”“租金表现偏弱”“风险较大”等判断。如果没有阈值、观察窗口、计算方法和阈值来源，这些词很难复核，也很难在不同产品之间复用。

因此，Skill 不能只要求模型给出判断，还要要求它说明判断依据。没有可靠行业阈值时，应明确写“缺少可参照阈值”或“无法判断”，而不是临时编一个标准。

### 3. 指标名称相同，不代表口径相同

REITs 披露里有很多容易混淆的口径：

- 期末出租率与期间平均出租率；
- 单季收入与年内累计收入；
- 可供分配金额与实际分派金额；
- 募集规模口径、评估值口径和市值口径的分派率；
- 合同租期与加权平均剩余租期；
- 披露值、根据累计值差分得到的计算值、研究假设。

项目曾经出现过把单季数放进带有“累计”含义的字段、把不同分母的分派率直接比较等问题。它们不是文字错误，而是会改变投资结论的口径错误。

因此，我把期间、单位、聚合方式、分母、时点/期间属性写进数据规则和测试。无法直接比较的数据应标记为不可比，不能为了表格完整而强行补数。

### 4. 公式没有适用期间，容易把历史规则错误地套到未来

一个公式即使在某份报告中正确，也不代表它在所有年份、所有产品和所有披露制度下都适用。数据口径、会计处理和披露规则可能变化。

因此，公式需要记录来源、适用期间、输入字段和版本；当制度或披露口径变化时，不能默默沿用旧公式。

### 5. 缺失数据不是让模型“想办法补齐”的邀请

资料缺失时，模型很容易用行业惯例或推测值填补空白，最后写出看似完整、实际无法验证的结论。

本项目逐渐采用“已证实、部分支持、无法判断、不可比、来源不可得、数据质量警告”等证据状态。缺失本身也要成为研究结果：说明缺什么、为什么缺、会影响哪项判断，以及下一步怎样验证。

### 6. FLOW 的执行顺序不等于投资报告的叙事顺序

这是本项目第六轮重构最重要的认识。

FLOW 回答“研究员怎样得到数字和结论”；正式报告回答“投资者为什么应该相信这个判断，以及它对投资决策意味着什么”。

如果直接把 FLOW 的步骤改成报告章节，报告就会像一份工作日志：做了什么、检查了什么、运行到哪一步，而不是围绕投资问题展开论证。

因此，项目增加了独立的 `reits-report-writing` Skill，把研究分析与报告写作分开。报告先提出投资论点，再组织证据、机制、反面证据和投资含义；自检、口径裁决和执行过程放入附录或运行记录。

## 二、我对 Skill 的理解：它不是一段更长的 Prompt

我现在把 Skill 理解为一套可复用的研究工作规范，而不是一次性指令。

Prompt 通常告诉模型“这次要做什么”；Skill 还要告诉模型：

1. **何时使用**：适用投前、投后还是专题研究，任务边界是什么。
2. **需要什么输入**：标的、期间、文件、数据字段和必要前提。
3. **怎样执行**：文件定位、数据提取、口径统一、计算、归因、估值和写作的步骤。
4. **怎样判断**：指标定义、阈值、公式、证据等级和反证要求。
5. **何时停止**：关键资料缺失、口径不可比或模型输入不充分时，不能继续给出确定性结论。
6. **产出什么**：事实底稿、数据矩阵、假设登记、模型、Claim 裁决、来源索引和正式报告。
7. **怎样验证**：计算对账、来源回查、自动化测试、人工审稿和版本记录。

我也认识到，Skill 并不会自动让模型拥有专业投资判断。它的价值是把研究过程中的关键约束显式化，让模型少犯可预防的错误，并让研究员更容易复核。投资假设是否合理、证据是否足以支持因果判断、最终是否值得投资，仍需要研究员负责。

## 三、这个 GitHub 项目在做什么

项目不是只生成两份 Prompt，而是尝试建立一条从公开披露文件到正式研究报告的工作链。

### 1. 四个 Skill 的分工

| Skill | 定位 | 主要职责 |
|---|---|---|
| `reits-post-investment-monitor` | 投后业务 Skill | 定期运营指标、区域/项目归因、收入与可供分配金额趋势分析 |
| `reits-pre-investment-analysis` | 投前业务 Skill | 交易结构、基础资产、运营、财务、现金流预测、估值和风险收益分析 |
| `reits-report-writing` | 报告写作 Skill | 将上游研究产物组织成正式投研报告，进行两轮审稿和字数核验 |
| `research-report-to-flow` | 方法论 Skill | 从卖方研报中提取研究逻辑、数据需求、判断规则和可执行流程 |

其中前两个是老师要求的两类核心业务 Skill；报告写作 Skill 是为了解决“分析做完了，但报告不像正式研报”的问题而增加的下游能力；研报转 FLOW Skill 则负责研究方法论的迁移。

### 2. 项目工作链

```text
公开披露文件
    ↓
文档索引、分类与解析
    ↓
数据提取、口径统一、质量检查
    ↓
投后经营分析 / 投前深度分析
    ↓
数据矩阵、假设登记、Claim 裁决、现金流模型
    ↓
独立报告写作与两轮审稿
    ↓
正式投研报告 + 来源索引 + 模型 + 测试记录
```

项目把“取数与计算”和“研究表达”拆开，是为了避免报告直接照搬 FLOW 的执行步骤。

### 3. 三个真实案例

| 案例 | 任务 | 主要分析内容 | 仓库产出 |
|---|---|---|---|
| 中金普洛斯仓储物流 REIT（508056） | 投后跟踪 | 2025Q1–Q4 运营指标、项目归因、收入和可供分配金额，重点看 Q4 | `outputs/case_01_glp_reit/` |
| 华夏深国际仓储物流 REIT（180302） | 投后跟踪 | 2025Q1–Q4 运营指标、杭州/贵州项目差异、收入与可供分配金额变化 | `outputs/case_02_huaxia_shen_international/` |
| 中信建投首农食品集团 REIT（508601） | 投前框架下的深度研究及上市后验证 | 交易结构、资产、租约、财务、现金流、估值、分派率、IRR 和风险 | `outputs/case_03_sinofarm_reit/` |

需要特别说明：首农当前报告使用了 2026 年更新招募说明书和第三季度报告，分析基准日为 2026-11-05。因此它是对发行定价的复核，并结合上市后资料验证原有假设；它并非严格冻结在发行时点、完全不使用未来信息的“纯投前决策报告”。下一阶段需要把发行时信息集与上市后验证信息集分开。

## 四、三个案例得到了什么结果

这里列出的是报告中的研究发现，不代表所有假设都已被外部独立验证。

### 案例一：普洛斯 REIT——整体指标掩盖了项目分化

报告发现，2025 年出租率同比改善，但租金单价同比下降，呈现“量升价降”的特征。进一步拆到项目后，淀山湖对整体出租率形成明显拖累，部分项目则提供正向贡献。

收入、现金流、可供分配金额和实际分派金额也并非同方向变化。报告因此没有把“分派表现”直接等同于“经营表现”，而是进一步检查其他调整项、历史结转和年报审计口径。

**Insight：** REITs 的整体出租率和整体收入只能说明结果，不能直接说明经营质量。区域/项目层面的加权归因，才能帮助研究员定位真正需要跟踪的资产。

报告：`outputs/case_01_glp_reit/report_508056_2025Q4.md`

### 案例二：华夏深国际 REIT——收入下降与可供分配金额上升可以同时发生

报告发现，2025 年收入下降，而可供分配金额同比上升。进一步分析发现，折旧摊销及相关调整会改变两者之间的关系；这种会计结构效应有上限，不能简单外推为未来分派能力持续改善。

项目层面，杭州更突出的是出租率波动，贵州更突出的是租金下行。把两者合并成一个“整体经营承压”的结论，会掩盖不同资产的问题性质。

**Insight：** 研究员不能只看收入或可供分配金额中的一个指标。必须追踪收入、成本、EBITDA、经营现金流和可供分配金额之间的传导关系，并区分短期会计效应与可持续经营改善。

报告：`outputs/case_02_huaxia_shen_international/report_180302_2025Q4.md`

### 案例三：首农食品集团 REIT——分派率不能替代投资回报率

首农案例中，报告区分了几个容易被混用的数字：

| 指标 | 报告采用的数值 | 含义 |
|---|---:|---|
| 2026 年披露分派率 | 6.22% | 含首年资金余额等一次性因素的披露口径 |
| 2026 年规范化分派率 | 5.08% | 按规范化现金流口径还原 |
| 2027 年预测分派率 | 5.60% | 管理人预测口径 |
| 中性情景持有到期 IRR | 0.55% | 纳入 2028 年租约重定价等研究假设 |
| 评估假设下 IRR | 2.67% | 沿用评估预测增长假设的情景结果 |

报告还识别出几个值得进一步验证的风险：

- 2028 年上半年有较大比例的已租面积集中到期；
- 翠微股份占比较高，且其经营与付款情况值得持续跟踪；
- 未来资本性支出预测与历史支出水平存在较大差异；
- 评估报告原件未单独取得，部分估值参数只能依据招募说明书转述，不能声称完成了对原始评估模型的独立复核。

**Insight：** 高分派率不必然意味着高投资回报。对有明确收益期限、期末终值假设不确定的资产，必须同时研究现金分派、初始投资价格、各期现金流时间和退出价值。情景分析也不能把管理人的预测直接当作唯一未来路径。

报告：`outputs/case_03_sinofarm_reit/report_508601.md`

## 五、项目目前取得的成果

### 1. 从单一 Prompt 扩展为分层的 Skill 体系

目前形成了两个核心业务 Skill、一个报告写作 Skill 和一个研究方法论 Skill。分析层与写作层分离，避免把执行流程直接变成报告目录。

### 2. 完成三个真实案例的运行

两个投后案例覆盖 2025 年四个季度，并重点分析 2025Q4；首农案例完成交易结构、运营、现金流、估值和风险收益分析，并建立独立情景测算。

### 3. 建立了可追溯的数据和模型资产

仓库包含：

- `source_documents/source_index.csv`：披露文件索引；
- `models/data_matrices.xlsx`：运营数据矩阵；
- `models/cash_flow_model.xlsx`：首农现金流模型；
- `models/scenario_2028.csv`：到期重定价情景；
- 各案例的 `claims_verdict.csv`、`assumptions.csv` 和 `run_log.md`。

项目审计记录本地归档 60 份 PDF，索引为 62 条记录（60 份实体文件及 2 条缺口登记）。其中 52 份有可用文字层，8 份扫描件尚未完成 OCR。原始 PDF 未提交 GitHub，因此 Clone 仓库不能直接复现原始文件处理流程；需要按索引重新获取文件。

### 4. 六轮迭代把真实错误转化成规则

项目迭代记录包括数据抽取、口径判断、模型、测试体系、资料完整性和报告形态等方面的修正。比较重要的是：发现错误后，不只修正当次报告，还把错误转化为 Skill 规则、数据检查或回归测试。

### 5. 建立自动化验收

当前仓库记录 153 条断言，结果为 151 PASS、0 FAIL、2 SKIP。测试覆盖计算对账、数据质量、Skill 结构、回归和报告形态。

这些测试证明预先定义的检查项通过，不等于证明所有投资判断正确。投资结论仍需人工检查证据、假设和因果关系。

### 6. 形成正式报告，而非只交付运行日志

第六轮增加 `reits-report-writing`，三份报告改为面向读者的投研结构：投前报告采用十章结构，投后报告采用八节结构；FLOW 编号、内部状态码和运行过程主要移至附录或运行日志。

首农报告的中文正文已经超过 15,000 字要求。当前报告封面、README 与机器指标文件中的精确字数仍有 29 个字符的差异，交付前应重新运行统计脚本并统一。

## 六、哪些工作体现了 AI 的增量价值，哪些仍然需要人

我不认为这个项目证明了 AI“比人更会投资”，也不认为这些工作是人类无法完成的。更准确的价值在于：把原本依赖研究员逐份阅读、手工对账和个人记忆的工作，变成可以规模化执行、保留证据、重复检查的流程。

| 研究工作 | AI 可以提供的增量价值 | 仍需研究员负责的部分 |
|---|---|---|
| 多份披露文件处理 | 批量分类、提取、建立索引 | 核对文件版本、关键原文和法律含义 |
| 跨季度指标整理 | 统一字段、单位、期间和计算口径 | 判断指标是否可比、是否适用于该资产 |
| 异常与背离识别 | 同时检查多个指标及其变化 | 判断因果机制是否成立 |
| 现金流情景测算 | 快速重算多组假设并比较结果 | 选择合理参数、识别模型遗漏 |
| 证据与结论追踪 | 把结论关联到数据、页码和假设 | 判断证据强度是否足以支持结论 |
| 报告生成 | 形成结构化初稿、图表和附录 | 审稿、挑战观点、形成最终投资意见 |

我希望形成的是“AI 提高研究执行能力，研究员掌握研究判断与投资责任”的协作方式。

## 七、目前的不足与下一步如何进步

项目已经形成主体成果，但还不能称为成熟的机构级投研产品。下一阶段不应只增加 Skill 数量，而应提高研究准确性、复现能力和跨标的泛化能力。

### 1. 严格区分投前信息集与上市后验证信息集（最高优先级）

首农当前报告使用了发行后更新资料和 2026 年第三季度报告。下一步应建立两套时间截面：

- **发行时点投前报告**：只使用发行时已经公开的信息，回答当时是否值得认购；
- **上市后验证报告**：使用后续季报和年报，检查原预测是否兑现、哪些假设发生变化。

这样可以避免用事后信息评价当时的投资决策，也能真正检验投前预测能力。

### 2. 提高现金流模型的时间精度

目前部分 IRR 计算采用等间隔年度现金流。下一步应把实际认购、分派和退出日期纳入模型，增加基于真实日期的 XIRR 计算，并对分派时点、首期期间和终值假设进行复核。

### 3. 完善原始资料解析

对 8 份扫描件进行 OCR，优先处理可能影响估值、法律条款和运营判断的文件。对 OCR 结果保留页码、置信度和人工抽检记录，不把低质量识别结果当成原始事实。

同时继续完善官方披露渠道探针，保留第三方备用渠道，并明确每份文件的实际获取来源。

### 4. 从三个案例扩展到跨业态验证

目前三个案例覆盖仓储物流和商业不动产，但样本数量不足以证明全市场适用。

下一步可以增加不同类型的公募 REITs，例如产业园区、收费公路、保障性租赁住房、能源基础设施等，检查：

- 指标体系是否需要按业态调整；
- 阈值能否跨业态使用；
- 收入与可供分配金额的传导机制是否不同；
- 现有 Skill 是否会把某一类资产的经验错误迁移到另一类资产。

### 5. 增加“反事实”和“预测准确率”评估

不仅检查报告有没有写出结论，还要追踪结论后来是否兑现。

例如：

- 投前预测的出租率与实际出租率差多少？
- 租金预测误差来自价格还是面积？
- 可供分配金额偏差来自 EBITDA、资本性支出还是营运资本？
- 哪类假设最容易出错？
- 哪些风险提示后来真正发生？

长期看，Skill 的质量应该由预测误差、数据错误率、证据覆盖率和人工修改量衡量，而不是由报告长度或测试数量衡量。

### 6. 建立独立的人工审稿与模型风险机制

自动化测试不能代替专业判断。下一步应要求每份报告由研究员重点复核：

- 核心投资论点是否有反证；
- 估值方法是否适合该资产；
- 现金流模型是否遗漏重要支出；
- 情景假设是否有现实依据；
- 是否存在重复计算或错误归因；
- 最终评级是否与全文证据一致。

## 八、我对这个项目最终想达到的目标

我最初的目标是把老师给出的两类 REITs 分析任务做成 Skills。实际完成后，我发现更有价值的方向不是让模型一次性写出一篇更长的报告，而是建立一个可以不断积累研究经验的系统：

- 新增一只 REITs 时，不必从零开始设计分析流程；
- 新增一份披露文件时，可以按统一规则识别、提取和核验；
- 发现一次口径错误时，可以把它转化为规则和测试，避免下次重复发生；
- 形成一个投资观点时，可以回到数据、模型和假设检查它是否站得住；
- 后续实际经营结果出来时，可以回头检验之前的预测和风险判断。

**我希望最终实现的不是“让 AI 替研究员写研报”，而是让 AI 成为研究员的一套可审计、可复用、可持续改进的研究基础设施。**

它可以承担大量重复的信息处理、口径检查、计算和初稿组织工作，让研究员把更多时间放在真正重要的事情上：提出问题、理解资产、挑战假设、判断风险，并作出投资决策。
