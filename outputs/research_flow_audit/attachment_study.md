## 0. 先给结论（六条）

1. **模板是统一的，且是"强约束型"的**：11 套文件的 METADATA 顶层字段 **10/10 完全一致**，子字段 **6/6 完全一致**，SKILL 正文结构 11/11 同构。这套规范可以直接继承，不需要重新设计。

2. **模板的致命短板不在文风，在 schema 的表达力**：`required` 一个字段同时背了"缺了会不会崩""缺了结论还成不成立"两件事，导致 **11/11 的主导研报核心论据被系统性降级**。531887 最典型：西方石油 PE（§3.2 全节、13x 锚）与中国神华/兖矿 PE（§2.3 溢价归因）全部 `required: false`。

3. **数据层是空的**：11 套共 **729 条** data_requirements，`source_id: null` **729/729 = 100%**。没有任何一篇做过数据源探针。这意味着 11 个 FLOW 在真实环境里 **一条都跑不通**——它们是"结构完整的空壳"，不是"可执行流程"。

4. **判断层是无标尺的**：11 套 FLOW 里"高位/中位/低位""强/中/弱"这类三档判断大量出现，但 `阈值` 一词在 531887/531931/531936/531998/532300/532411 中 **出现 0 次**；`敏感`（敏感性）**11/11 出现 0 次**；`目标价` **11/11 出现 0 次**。判断全靠 LLM 临场发挥。

5. **时间适用性完全缺失**：`formula_version` / `valid_from` **11/11 = 0**，`Step 0`（数据预处理）**11/11 = 0**。531887 的长协公式在研报里明确分了三段（2022–24 三指数、2025 四指数、2026 产地月度浮动），FLOW 却只写了一个"50%×基准价+50%×指数均值"，并把当期权重的公式用于任意历史期。

6. **两个 ZIP 的容器格式自己就不一致**：531887 用 `<<<FILE: X>>>…<<<END: X>>>` 自闭包，其余 10 套用 `<<<FILE: X>>>…` 加文末单个 `<<<END>>>`。拆分脚本照抄第一种写法，结果 10/11 的 SKILL/FLOW/METADATA **丢了结尾标记**（只有 531887 保留）。这是新 Skills 必须修的工程细节。

一句话：**这套模板值得继承的是"文件组织的纪律"，不值得继承的是"用指标清单代替论证结构"的抽取方式。**

## 4. FLOW.md 的共同规范

### 4.1 四段式骨架

```
--{abstract}--          ① 思考路径（4–6 条编号句，"前提→核心矛盾→目标→方法→要求"）

  2. …
--{/abstract}--

[输出示例]：                ⑥ 表头模板 + "xx%" / "—" 占位
```

### 4.3 动作命名的动词化程度差异很大

- 好：`测算长协公式价并校验实际长协价`（531887 #6）、`测算油煤比并检验高耗能出口成本优势`（#10）——可判定、有宾语、有验证关系。
- 差：`#1 [数据]`（531887 首行动作无标题，只有"按 METADATA 获取全部指标"）、`#8 [非数据]`（531936 多处以序号代标题）。

**结论：动作名必须是"动词+对象+判据"，不能是"取数"或留空。** 这一点新 Skills 写成强制校验项。

## 6. 不同研究类型的 FLOW 设计差异

按"论证结构"而不是"行业"分类，11 篇可归为四型：

### 型 I：机制演进型（531887）
- 结构：`供需/集中度 → 定价机制（长协）→ 成本传导 → 供给约束 → 估值体系`
- 特征：**非数据动作承载制度史**（#4 定价权变迁、#7 长协七阶段、#11 电力改革、#15 估值体系重塑，占 29%）；大量"阶段对比表"（表 3/表 4）在 FLOW 里被压缩成一句"梳理…演进"。
- 缺陷：研报最硬的部分（表 3 七阶段定价公式、表 4 六年履约率要求）在 FLOW 中 **没有对应的结构化动作**，只在 #7 的"输出示例"里留了三条 bullet。

### 型 II：要素拆解型（531931 AI 制药、531985 具身智能、532411 企业 AI）
- 结构：`要素 A → 要素 B → 要素 C → 标杆公司解剖 → 估值`
- 特征：**非数据动作占比最高（531985 58%、531931 42%）**，因为核心论点是"技术路线尚未收敛""数据是瓶颈"这类**不可直接观测的判断**。
- 缺陷：这类"不可观测因子"被写成"梳理…综述 + 结论句式示例"，等于把最难的判断交给 LLM 自由发挥；`角色/路线收敛度` 没有代理指标。

### 型 III：高频跟踪型（531936 季度、532211 月报、532274 热点复盘）
- 结构：`本期变化 → 量价结构 → 订单/排产 → 业绩验证 → 估值 → 风险`
- 特征：指标频率高（日/周/月/季），强调环比与"本期 vs 上期"，动作数适中但**每个动作的公式最具体**（如 531936 的"滞后 2 季度 Capex / 环比营收增量"）。
- 缺陷：**公式最具体的地方最容易错**——531936 的资本密集度在"环比营收增量为负或为零"时无保护；532211 的"全船型订单运力比 | 高位/低位/中性"无 bands。

### 型 IV：条件清单型（532079 三重底、531998 三板块）
- 结构：`条件 1 底部 → 条件 2 底部 → 条件 3 底部 → 弹性测算 → 综合`
- 特征：**判断是"多条件同时满足"的合取**，最接近"可裁决"的形态；532079 的分位用法最多（`分位` 43 次、`PB` 42 次），因为"底部"本身是分位概念。
- 缺陷：合取判断没有"部分满足"的中间态——三条底满足两条时输出什么，FLOW 未定义。

### 型 V：单一公司型（532198 SHEIN、532300 花知晓）
- 结构：`公司业务 → 行业空间 → 竞争格局 → 供应链/产品 → 财务 → 估值`
- 特征：**指标最密（112/37 条）但私有公司数据可得性最差**（SHEIN 未上市，58 条 false）；大量指标本质是"招股书一次性披露值"，被写成"年度"频率，实际不可重复取得。
- 缺陷：把"一次性披露"当"可跟踪时间序列"，是**频率造假**。

### 9.3 三个可复现的计算错误

**错误 1：长协公式跨制度套用（最严重）**

研报原文（表 3，p17）：

| 阶段 | 公式 |
|---|---|
| 2016–2021 | P = 50%×535 + 50%×综合指数 |
| 2022–2024 | P = 50%×675 + 50%×三指数（国煤综合、环渤海、CCTD 秦皇岛）均值，约束 570–770 |
| 2025 | P = 50%×675 + 50%×四指数（+CECI 沿海电煤采购）均值，约束 570–770 |
| 2026– | 港口：675 + 四港口指数；**产地：当地中值基准（晋 470/陕 420/蒙西 360/蒙东 250）+ 四产地指数，月度调整** |

FLOW #6 原文只有一条：
```
公式价 = 50% × inputs.当前港口长协基准价 + 50% × 指数均值
（可用指数均值，缺失项剔除并在输出标注）
```
→ 用"当前"基准价和"当前"指数口径回算任一历史期，等于把 2025 年的制度装进 2017 年。**这不是精度问题，是可比性问题。**

**错误 2：长协溢价口径混用**

FLOW #12：`长协溢价 = 长协最近12个月均价 - 对应成本`，并注明"若无法精确匹配产地，则用主要产地均值并标注"。
但长协价是**秦皇岛港 5500 大卡下水价（含运费）**，成本是**坑口完全成本**。二者相减把运费、热值差、下水费全部算成"溢价"。研报自己并没有做这个减法，而是用"成本曲线 + 边际成本定价"定性说明（p24 首段）。

**错误 3：在建产能/产量 的量纲**

FLOW #13：`在建产能/当前产量 = 在建产能 ÷ 近12个月原煤产量加总`。分子是"万吨/年"（能力），分母是"万吨"（年度流量），商在数值上成立但语义是"产能/年产量"，需显式写成"在建产能（万吨/年）÷ 年化产量（万吨/年）"，否则跨年比较会漂。

## 11. 对新 REITs Skills 的设计启示（10 条，直接落到后续设计）

1. **继承四文件与四段骨架**，不自创工程结构。新 Skills 的 SKILL/FLOW/METADATA 必须与附件同构，唯一新增是 `_raw_response.txt` 的双分隔符统一为自闭包写法。

2. **METADATA 保留全部 10 个顶层字段与 6 个子字段名**，只做**加法**：
   - 在 data_requirements 内新增 `execution_required` / `thesis_required` / `importance` / `evidence_role` / `missing_data_impact`（对应用户 2.3 的四问），`required` 保留为兼容字段并由 `execution_required` 派生，**不删除**。
   - 新增 `bands` / `direction` / `window` / `threshold_source`（对应用户 2.7）。
   - 新增 `source_probe`（实际探针结果）、`formula` 块（含 `version/valid_from/valid_to`）（对应用户 2.6/2.8）。
   - 新增字段必须在 FLOW 中真的被引用，否则不加。

3. **FLOW 必须从 Step 0 开始**：Data Ingestion & Preprocessing，产出 `data_manifest.md` + 标准化数据集；后续动作只读产物，禁止二次清洗（直接治附件 11/11 的病）。

4. **动作 = 一个论点（claim）的裁决器**，不是"算一个指标"。动作名写成"动词+对象+判据"，动作数 ≈ 论点数（531887 的 17 个动作应压到 6–7 个裁决动作 + 1 个数据动作 + 1 个报告动作）。

5. **三档判断必须外置标尺**：每个 `高/中/低` 都要有 `direction + bands + window + threshold_source`；给不出来就输出 `UNDEFINED_THRESHOLD`，不许硬判。附件里 35 次"高/中/低"零标尺的做法不能再出现。

6. **公式必须带版本与适用期**：长协公式的三段演进、REITs 的可供分配金额口径（2023 年准则解释、2024 年指引修订）都属于必须分段的对象。`valid_from/valid_to` 为空 = 每期必须复核。

7. **不可判定是合法输出**：`CONFIRMED / PARTIALLY_SUPPORTED / INDETERMINATE / NOT_COMPARABLE / SOURCE_UNAVAILABLE / DATA_QUALITY_WARNING / UNDEFINED_THRESHOLD` 七态写进 FLOW，且**报告首页先出"不可判定清单"**。

8. **数据源必须实测**：附件 645 条 `source_id` 全空是最大的教训。新 Skills 的每条 source 必须有 `probe` 结果（ok/paid/build/none）与实测样例；拿不到就写 `SOURCE_UNAVAILABLE`，绝不编造。

9. **区分"可重复取得"与"一次性披露"**：532198 把招股书值标成"年度"的错误，在 REITs 场景等价于把"招募说明书预测的 2027 年收入"当成"已实现年度值"。新 Skills 的数据模型必须区分 `actual / disclosed_forecast / independent_forecast`（对应 3.7 第六部分）。

10. **同一行业的不同问题要能共存而不冲突**：531887 与 532274 同为煤炭却互不兼容，说明缺少"行业级数据契约"。REITs 两个 Skill 应共用一份数据契约（运营指标字典、期间口径、可供分配金额公式族），只在裁决层分叉。
