### 问题记录 P-01：整体指标抽取为 0

- **现象**：首轮运行 `parse_ops()` 时，§4.1.2 整体指标全部为空（值为 0）。
- **定位**：季报中 §4.1.2 表格位于 §4.1.3 之前，原代码把「第一个 `资产项目名称` 之前」当作整体段，而该段实际被页眉截断。
- **修复**：改为取 `4.1.2` 与 `4.1.3` 标记之间的文本；若标记缺失，fallback 到第一个运营指标行前 2,500 字符。
- **验证**：修复后 Q1 出租率 90.59%、Q2 92.24%、Q3 88.83%、Q4 89.54%，与季报原文逐项核对一致。

### 问题记录 P-02：Q4 分项目数为 0

- **现象**：2025 年报的分项目运营表被解析为空。
- **定位**：2025 年报改用「**不动产**项目名称」，季报用「**资产**项目名称」，正则只匹配后者。
- **修复**：正则改为 `r"(?:资产|不动产)项目名称[：:]\s*([^\n]+)"`。

### 限制 R-01：Q4 只披露 5 个项目

2025 年报 §4.1.3 只列示空港、增城、淀山湖、顺德、望亭 5 个项目，**通州光机电缺失**。因此贡献度分解中的「其余 +0.71pct」是倒算项，不是实测项。已在报告 §3.2 与 `claims_verdict.csv` 的 C6 备注中标注。

### 限制 R-02：单季可供分配与年报差 0.68%

四季单季可供分配合计 337,472,828.59 元，年报 335,181,671.99 元，差 **2,291,156.60 元（0.68%）**。差额来源无法从公开材料定位（可能为年末审计调整）。已标 `DATA_QUALITY_WARNING`，不做强行抹平。

### 关键口径判断：实际分派 ≠ 可供分配

- 账面「实际分派 / 可供分配」= 430,470,192.84 / 335,181,671.99 = **128.4%**，**这个数没有经营含义**——分子含上年结转与宣告/实施时点差。
- 同口径比较应剔除结转：342,337,121.58 / 335,181,671.99 = **102.1%**，这才是判断「是否达到 90% 分配要求」的正确口径。
- 已在报告 §4.3 与 C4 中固化该口径。

## 3 claim 裁决（FLOW #19–#20）

6 条 claim，结论：**PASS 3 / FAIL 2 / INDETERMINATE 1**。

- C1（出租率 ≥90%，`each_period`）**FAIL**：Q3 88.83%、Q4 89.54% 击穿。若改用均值 90.30% 会误判为临界通过——聚合方式必须在建 claim 时写死。
- C2（租金同比 ≥0）**FAIL**：四季全负（−7.62 / −10.58 / −8.26 / −7.48）。
- C3（可供分配与测算无重大差异）**INDETERMINATE**：招募书测算期只到 2024-12-31，2025 年无官方预测，年报「无差异」表述不可核查。
- C4（分配 ≥90%）**PASS**：102.1%（同口径）。

**C3 是本案例最重要的方法论发现**：这不是数据缺失，是**预测断档**。投后跟踪失去了最重要的锚，只能拿行业惯例当阈值。
