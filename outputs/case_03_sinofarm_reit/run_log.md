## 9. 公式、数据口径与模型重构（2026-11-12）

### 9.1 已修正的确定性问题

- **2027 收入分项勾稽**：原 `nonrent_2027` 少计提成租金 2,849,696.97 元。原代码注释列有该项，但参数值 15,982,525.26 元实际只等于停车、多经及其他收入。现修正为 18,832,222.23 元（提成租金 2,849,696.97 + 停车 6,927,272.73 + 多经 8,305,252.53 + 其他 750,000），并增加 `validate_revenue_bridge()`，要求固定租金 + 非固定租金与 2027 披露总收入 254,760,101.02 元在 1 元容差内勾稽。
- **评估现金流增长率误作收入增长率**：原平滑增长模型把招募书转引的 2.78% 预测期现金流 CAGR 用作收入增长率，并固定 EBITDA margin 外推。现金流 CAGR 与营业收入增长率定义不同，缺少桥接时不得替换。本版不再使用该路径；2028–2044 主模型改为引用 `build_bottomup.py` 的中性到期重定价情景。2.78%/2.25% 保留为评估转引参数，不直接用于收入外推。
- **EBITDA 冒充 NOI**：原模型将 EBITDA 放入 `NOI_ROWS` 折现，并用于声称复现物业评估值及土地延长期限价值。该口径不成立；现已删除 `PV_NOI5` 和以 EBITDA 计算土地延长价值的函数。未取得原始评估报告及物业 NOI 定义前，不计算独立物业 DCF/NAV。
- **2028 年后营运资金**：原代码隐式将营运资金变动设为零。现将其显式定义为 `NWC_CHANGE_2028_PLUS = 0.0`，在模型输出和 Disclaimer 中标注为未验证占位假设，而不是披露事实。
- **投资者分配比例**：原 IRR 只使用 100% 可供分配金额作为现金流。现 Excel 同时计算 90% 与 100% 分配情景；两者均为边界情景，实际投资者现金流仍须按基金合同、实际分派决议及支付日期确定。
- **情景输出口径**：`scenario_2028.csv` 和 Excel 的 `5_到期重定价` 新增 `wc_change` 列；`2_模型` 链接中性情景，不再单独生成与情景引擎不一致的平滑增长公式。

### 9.2 标准公式与适用边界

- IRR 使用标准年度等间隔现金流定义，求解 NPV=0；90%/100%分别缩放投资者分派现金流。
- PV 使用标准折现公式，但基金层可供分配现金流的现值不是物业价值或 NAV。折现率必须与现金流层级和风险相匹配。
- 营运资金现金流调整采用 `−ΔNWC`；2028 年以后因缺乏应收/应付预测暂按零处理。
- 收入由固定租金、提成租金、停车、多经和其他收入构成；当前到期组公式仍为聚合情景近似。历史 76.83% 续租率为面积口径，应用于租金收入是口径代理，不是严格同口径推导。
- 收入至 EBITDA 的 0.81 传导系数来自税费和管理费比例的近似推导；在实际税基、收入类型及固定/变动成本未逐项核验前，仅用于敏感性，不视为通用行业公式。
- CAPEX 3.5%、利息及所得税合计年增 2%、2029 年后收入增长情景、聚合续租率、统一空置期及零终值均为模型假设，必须在报告中保持可见。
