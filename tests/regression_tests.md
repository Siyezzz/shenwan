# 回归测试（T-REG）

**对象**：三个案例的报告与模型文件
**执行**：`python tests/run_tests.py` 中的 `t_reg()`
**条数**：17
**当前结果**：17 / 17 PASS

## 这一组在防什么

前三组（T-CALC 计算、T-DQ 数据质量、T-SKILL 结构）验的是"做得对不对"。这一组验的是"**改完之后，原来对的还对不对**"。

投研报告有个特点：**改一处会牵连全局**。把 2026 年分派率的口径从 6.22% 改成 5.17%，看起来只动了一个数，实际上摘要表、估值章节、投资结论、敏感性分析可能都要跟着变。而人改文档时只盯着手上那一段，其他部分不动声色地过期了。

回归测试的作用就是：**每次改完，把那些"必须一直成立"的结论重新点一遍名。**

## 一、报告存在性与篇幅（T-REG-01、02，各 3 = 6 条）

| 案例 | 文件 | 中文字符 | 下限 | 判定 |
|---|---|---|---|---|
| 案例一 | `report_508056_2025Q4.md` | **4,230** | 3,000 | PASS |
| 案例二 | `report_180302_2025Q4.md` | **3,728** | 3,000 | PASS |
| 案例三 | `report_508601.md` | **17,559** | **15,000** | PASS |

**为什么投后 3,000 字、投前 15,000 字**：

- 投后是**跟踪**：核心是"这个季度发生了什么变化"，篇幅天然受限。3,000 字是下限，保证三层结构（运营 → 区域归因 → 收入与可供分配）每层都有实质内容，而不是只报数。
- 投前是**决策**：十部分必须逐一展开，且要容得下交易结构、现金流模型、估值、敏感性、风险。15,000 字是项目原始需求给定的硬指标。

**案例三的字数是补出来的，过程值得记**：初稿只有 **8,820** 中文字符，未达 15,000。补充过程中逐条回溯原文核对，结果**发现 4 处事实性错误**（详见 `iteration_log/ITERATION_LOG.md` 第 3 轮 C-1 至 C-4 与报告 §1.4）。

也就是说：**字数不够往往不是"话没写够"，是"没读透"**。真正把材料读进去，字数自然就上来了，而且过程中会发现问题。

## 二、关键数字仍在报告中（T-REG-03，3 条）

**检验**：每份报告里必须仍能找到一组指定的关键数字，字面完全匹配。

| 案例 | 点名保留的数字 | 实测 |
|---|---|---|
| 案例一 | `422,500,807.91`、`335,181,671.99`、`430,470,192.84`、`102.1%`、`−3.51pct`、`71,520,087.02` | 全部在位 |
| 案例二 | `74,401,200.00`、`4.98%`、`4.81%`、`25.12%`、`71.32%`、`4.36%`、`−25.55%` | 全部在位 |
| 案例三 | `2,739,656,060.87`、`141,689,193`、`5.17%`、`2.67%`、`18.22`、`20.93`、`8.30%`、`3.56 年`、`36.53%` | 全部在位 |

### 这些数字是怎么选的

不是挑"重要的"，是挑"**一旦消失就说明出了事**"的：

| 数字 | 为什么必须在 |
|---|---|
| `102.1%`（案例一） | 这是**剔除上年结转后的**同口径分派率。如果哪天报告里只剩 128.4%，说明那个更正被回退了 |
| `−3.51pct`（案例一） | 淀山湖单项目对整体出租率的拖累，是全篇唯一"季报没有、自己算出来"的数。它消失 = 归因分析被删了 |
| `4.36%`（案例二） | 这是**错误口径**的例子。它必须留在报告里，因为报告要展示"用它会得出错误结论"这个反例。**保留一个错数字，是为了说明它为什么错** |
| `2.67%`（案例三） | 核心结论。与 5.60% 并存才构成"分派率≠回报率"的完整论证 |
| `18.22`（案例三） | 使 IRR 达 5.60% 所需的终值。它是 2.67% 与 5.60% 之间的桥梁，缺了结论就断链 |
| `3.56 年`（案例三） | 季报披露的面积加权剩余租期。它是对"54.06% 长租约"误读的纠正依据 |

### 这条断言自己出过两次错

本轮自检时 `T-REG-03` 报了 2 个 FAIL：案例二缺 `188.00`、案例三缺 `18.22`。

- **案例三那个是真问题**：报告里写的是"18.2 亿元"，模型精确值是 **18.22 亿元**。差 0.02 亿元听着小，但同一份报告里 2.67% 和 6.47 亿元都是四位精度，终值只有三位精度，读起来像是估的。**已统一改为 18.22 亿元**（3 处）。
- **案例二那个是断言本身的问题**：`188.00` 在任何一版报告里都不存在，是断言写错了。已换成 `4.36%`——它才是这个案例真正必须保留的关键值（错误口径的反例）。

**这个区分很重要**：同样是"FAIL"，一个是文档错、一个是断言错。如果不去分辨，就会把断言改松了事，那等于把测试废掉。本项目的处理原则是：**先判断错在文档还是错在断言，再改对应那一侧。**

## 三、案例三的两条结论性断言（T-REG-04、05，2 条）

### T-REG-04 §1.4 四条更正公开声明

**检验**：报告中出现"本报告相对初稿的四条更正"或同时出现 `C-1` 与 `C-4`。

**为什么要求"公开更正"而不是"悄悄改掉"**：

初稿的四处错误不是笔误，是**方法上的误判**：

| 编号 | 初稿说法 | 事实 |
|---|---|---|
| C-1 | 运营管理费未披露具体费率 | 完整披露：A = 收入×5.3%，B = 收入×R（3%/1.5%/0 分档），激励费 = min[(实际NOI−目标NOI)×20%, B+A×50%]；2026 合计 **8.30%** |
| C-2 | 2026 税费及预留 75 万 vs 2027 3,059 万，差 40 倍 | 这两个数是"评估值×CapRate"反推的**残差**，招募书无此科目；真实机制是余额法 |
| C-3 | 2026 资本性支出 2,105 万 | 现金流量表 21,047,778.55 vs **测算表 15,460,400.00**（不含税），差 558.7 万 |
| C-4 | 54.06% 租约 10 年以上，未来十年只有 46% 需重新定价 | 该分类按**合同约定租期**，非剩余租期；季报面积加权剩余租期仅 **3.56 年** |

**悄悄改掉会让读者以为初稿本来就是这样**，而 C-2 的错误方式（把反算残差当成披露科目）恰恰是最容易复发的——它看起来像是"从数据里读出来的"。公开列示 + 写清根因，是唯一能防复发的方式。

**PASS**。

### T-REG-05 分派率不等于回报率

**检验**：报告中出现"分派率不等于回报率"这一表述，且必须与 IRR 并列。

**为什么单独立一条**：这是全项目**最重要的一个判断**，也是最容易被"看起来专业"的写法冲掉的——很多报告会用"分派率 5.60%，具备配置价值"这种句式，把现金分派率直接当作投资回报率。

**结论链**：

> 分派率 5.60%（每年现金分派）→ 但资产 19.24 年后归零、评估不设终值 → 持有到期 IRR 仅 **2.67%** → 差 **2.93pct** = 土地年限的价格

缺了任何一环，这个结论都不成立。所以断言要求"分派率不等于回报率"这句话必须在，且上下文有 IRR。

**PASS**。

## 四、模型文件结构（T-REG-06 ~ 10，5 条）

### T-REG-06 `cash_flow_model.xlsx` 含 5 个 sheet

| sheet | 作用 |
|---|---|
| `0_说明` | 模型口径、数据来源、使用限制 |
| `1_假设` | 19 行输入 + 弹性 1.18 |
| `2_模型` | 19 期（2026–2044），G 列为公式 |
| `3_输出` | 含 `=IRR(C19:C38)` |
| `4_敏感性` | 5×5 矩阵 + 折现率×增长率 |

**这条断言改过一次**：初版写"含 4 个 sheet"，模型后来新增了 `0_说明`（把口径声明写进文件本身，而不是只写在报告里），变成 5 个。断言未同步，报 FAIL。

**处理**：改为 5 个，并额外校验前三个 sheet 名必须是 `["0_说明", "1_假设", "2_模型"]` —— 不只是数量对，顺序也要对。**顺序有意义**：先说明、再假设、再模型，这是阅读顺序，也是"先定口径再算数"的强制约束。

### T-REG-07 模型 19 期（2026–2044）

**检验**：`2_模型` 第 5 行 A 列 = 2026，第 23 行 A 列 = 2044。

**为什么是 19 期**：商业土地 **2045-03-29 到期**，基准日 2026 年，剩余 **19.24 年**。模型取整 19 期（2026–2044）。

**这个期限是整篇估值结论的地基**：如果期限取 30 年或永续，IRR 会显著上升，"2.67%"这个结论就不成立了。所以期限必须被断言钉住。

### T-REG-08 `2_模型` 的 G 列是公式

**检验**：G 列单元格的值以 `=` 开头（实测 `=C5-E5-F5`）。

**为什么必须是公式**：如果 G 列是算好后贴进去的数值，模型就无法重算——改一个假设，下游全部不动，等于一张死表。**"可重算"是现金流模型的最低要求**，也是"可复现"的具体含义。

`=C-E-F` 对应：可供分配 = EBITDA − 资本性支出 − 利息及所得税。

### T-REG-09 `3_输出` 含 Excel IRR 公式

**检验**：`3_输出` 中存在以 `=IRR(` 开头的单元格（实测 `=IRR(C19:C38)`）。

**为什么要检 Excel 内置 IRR**：Python 侧 `tools/build_model.py` 用二分法自己实现了 IRR。两条路必须给出同一个答案（实测均为 **2.6688%**）。如果 Excel 里贴的是一个常数，就失去了交叉验证的意义。

### T-REG-10 `data_matrices.xlsx` 含 8 个 sheet

```
508056_1运营指标   508056_2区域归因   508056_3收入与可供分配   508056_4分项目收入
180302_1运营指标   180302_2区域归因   180302_3收入与可供分配   180302_4分项目收入
```

**8 = 2 个案例 × 4 层矩阵**，对应投后跟踪的三层结构（运营 → 归因 → 收入与可供分配）+ 分项目明细。

**为什么要拆成 4 层而不是一张大表**：一张大表会把时点值（出租率）和期间值（收入）混在一起，读者无法判断某一行该做同比还是该做环比。拆开后每层的口径是单一且明确的。

## 六、这 17 条的共同逻辑

1. **点名关键结论，不点名全部内容**。回归测试不是文档快照，是"这些结论必须一直成立"。
2. **保留错误示例**。案例二留着 4.36%，因为它是反例——**证明错误存在，比假装错误不存在更有价值**。
3. **结构断言要卡顺序，不只卡数量**。5 个 sheet 对了不够，还得是"说明 → 假设 → 模型 → 输出 → 敏感性"。
4. **FAIL 先分责**。文档错改文档，断言错改断言；不分清就改松，测试会废掉。

## 七、本组未能覆盖的部分

- **观点一致性未检**：断言只验数字在不在，不验"摘要表的结论与正文 §8 的结论是否一致"。这是一个已识别但未自动化的风险点——案例三的评级在迭代中由"中性偏正面"改为"中性偏负面"，改动点分散在摘要表、§11 结论、§1.4 更正声明三处，本次靠人工逐处核对确认一致，脚本无法判断；
- **数值口径未检**：断言 verifies `4.98%` 在报告里，但不验它是不是用在正确的语境（是否用了正确分母）。这由 `T-DQ-09` 的 `evidence_ref` 和人工复核承担；
- **跨案例一致性未检**：三个案例对同一指标（如"分派率"）的定义是否一致，没有断言——因为三个案例场景不同（两个投后、一个投前），强行统一反而会掩盖差异。
