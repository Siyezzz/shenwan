# 数据质量测试（T-DQ）

**对象**：`outputs/_panel/*.csv` 长表面板 + 三个案例的 `claims_verdict.csv`
**执行**：`python tests/run_tests.py` 中的 `t_dq()`
**条数**：24
**当前结果**：24 / 24 PASS

## 面板的数据结构

面板是长表（long format），一行一个观测：

| 字段 | 含义 |
|---|---|
| `code` | 基金代码 |
| `period` | 期间标识（2025Q1 / 2025H1 / 2025FY …） |
| `metric` | 指标名，必须符合 `base[_suffix]` 规范 |
| `value` | 数值 |
| `unit` | 单位 |
| `anchor` | 页码锚点，指向原始 PDF 的具体页 |
| `source_file` | 来源文件名 |

**为什么用长表而不是宽表**：宽表会把"期间口径"藏进列名（如 `occ_2025Q4`），一旦口径变化就无法表达。长表把口径放在 `period` 与 `metric` 后缀里，可以做显式校验。

## 一、面板完整性（T-DQ-01 ~ T-DQ-04，各 2 个文件 = 8 条）

| ID | 检验 | 508056 实测 | 180302 实测 |
|---|---|---|---|
| T-DQ-01 | 面板文件存在 | 存在 | 存在 |
| T-DQ-02 | 行数下限 | **746 行**（下限 700，季度多、项目多） | **141 行**（下限 130，成立不足两年） |
| T-DQ-03 | `value` 无空值 | 0 条空值 | 0 条空值 |
| T-DQ-04 | 每条数据有页码锚点 | 0 条缺锚点 | 0 条缺锚点 |

### 为什么没有空值

**空值不是"没数据"，是一个判断。** 项目规定空值必须显式五态之一：

| 写法 | 含义 |
|---|---|
| `NA` | 该期该指标本就不适用 |
| `0` | 真实为零（如某租户全年租金收入为零） |
| `未披露` | 管理人有该指标但本期未披露 |
| `不适用` | 口径上不存在（如单季度报告不披露年度累计） |
| `SOURCE_UNAVAILABLE` | 数据源不可得 |

如果允许空字符串进面板，"未披露"和"抄漏了"就无法区分——前者是事实，后者是错误。所以 T-DQ-03 要求 `value` 字段**一条空值都不能有**，要么有数，要么是上述五态之一。

### 为什么强制页码锚点

**这是可回溯性的最低门槛。** 任何进面板的数，必须能指回某份 PDF 的某一页。做不到这一点，报告里所有引用就都是"据说"。

实践中这条规则救过一次：案例一某季度出租率抄错，靠锚点回查该页才发现。

## 二、指标命名规范（T-DQ-05，2 条）

**检验**：所有 `metric` 能否解析为 `base + suffix`，且 `base` 在指标字典内。

**规范出处**：`skills/reits-post-investment-monitor/METADATA.md` 的 `metric_naming`

| 部分 | 取值 |
|---|---|
| `base` | `revenue` / `dist` / `distributable` / `distributed` / `net_profit` / `cfo` / `ebitda` / `occ` / `rent` / `rent_avg_period` / `wale` / `collection` / `area_leasable` / `area_leased` |
| `suffix` | 空（本期原值）/ `_prev`（上期同口径，供算差）/ `_yoy`（同比变动，单位 pct）/ `_cum`（本年累计）/ `_q`（单季差分，非披露原值） |

**当前结果**：508056 有 **24 个** metric（746 行）、180302 有 **23 个** metric（141 行），全部通过。

**这条规则的由来（本轮真实修复）**：

首轮实现的断言用的是**硬编码白名单** `{revenue_cum, dist_cum, occ, rent, wale, collection, area_leasable, area_leased, ebitda}`，结果 508056 报 17 个"越界"、180302 报 16 个。检查后发现：不是数据错，是**规范本身没写下来**。面板里合法地用着 `occ_prev`、`rent_yoy`、`distributable_q` 这些命名，但 METADATA 里没有一处说明 `_prev` / `_yoy` / `_q` 是什么意思。

**处理**：不是放宽断言去迁就数据，而是先在 METADATA 补 `metric_naming` 把规范定义清楚，再让断言按规范解析。这样断言仍有约束力（写 `occ_rate` 或 `occupancy` 仍会红），但约束的是真规范，不是测试作者脑中的白名单。

**为什么 `_q` 必须单独标记**：`_q` 结尾的列是由累计值差分算出来的，**不是披露原值**。如果与披露值混用，一旦读者误以为是原值去核对 PDF，会发现对不上。规范要求 `_q` 列必须在 `run_log` 写明差分公式与源列。

## 三、时点值与期间值不可混（T-DQ-06，1 条）

**检验**：出租率指标中不得出现 `avg` 类字段。

**当前结果**：PASS。508056 的 `occ` 记录共 **40 条**（整体 1 条 + 分项目多条 × 多期），无一条为均值口径。

**为什么重要**：出租率、租金单价、剩余租期、收缴率都是**期末时点值**。如果用"季度平均出租率"，会平滑掉季末的突变——而突变恰恰是最该被看见的。

**实例**：案例一中淀山湖项目 9 个月内出租率掉 22.5pct，且是逐季下台阶。若用四个季度的平均值，这个故事会被抹平成一个温和的小幅下降。

**规则**：时点指标取期末快照，不取平均；期间指标（收入、可供分配、CFO）取累计或单季差分，不取时点。

## 四、单位不可比必须显式声明（T-DQ-07，1 条）

**检验**：508056 剩余租期最大值 > 100（单位：天），180302 最大值 < 20（单位：年）。

**实测**：508056 max **957.54**（天）/ 180302 max **1.98**（年）

**为什么这条是必要的**：

两只基金披露同一指标用了**不同单位**。508056 用"天"（389.71 天），180302 用"年"（1.55 年）。如果不做单位校验，把两个数放进同一张对比表，会得出"508056 剩余租期是 180302 的 251 倍"这种荒谬结论。

**处理方式**：不换算，直接判 `NOT_COMPARABLE`。理由：换算会引入精度假设（一年按 365 天还是 366 天），而两只基金的租约结构本就不同（508056 长租约、180302 短租约 1–2 年），换算成同一单位也改变不了"结构不可比"这个事实。

**结论**：跨基金对比时，剩余租期这一项只能各自陈述，不能排序比较。

## 五、claim 完整性（T-DQ-08 ~ T-DQ-11，各 3 案例 = 12 条）

| ID | 检验 | 案例一 | 案例二 | 案例三 |
|---|---|---|---|---|
| T-DQ-08 | `claims_verdict.csv` 存在且 ≥6 条 | 6 条 | 7 条 | 11 条 |
| T-DQ-09 | 每条 claim 有 `evidence_ref` | 0 条缺 | 0 条缺 | 0 条缺 |
| T-DQ-10 | `verdict` 取值在七态内 | 通过 | 通过 | 通过 |
| T-DQ-11 | 每条 claim 有 `aggregation` | 0 条缺 | 0 条缺 | 0 条缺 |

### T-DQ-09 为什么不能松

**没有证据引用的 claim 不是 claim，是观点。** 报告里可以写观点，但那部分不进裁决表。裁决表里的每一条都必须指得出"哪份文件、哪一页、哪张表"。

### T-DQ-10 的七态

`PASS` / `FAIL` / `INDETERMINATE` / `PARTIALLY_SUPPORTED` / `NOT_COMPARABLE` / `SOURCE_UNAVAILABLE` / `DATA_QUALITY_WARNING`

注意这里 `PASS` / `FAIL` 是**裁决结果**，另外五态是**不可判定或需附条件**的情形。允许"说不清"是本方法论的核心设计——一个只能输出"通过/不通过"的流程，遇到口径冲突时只能硬判，而硬判就是错的开始。

### T-DQ-11 为什么 `aggregation` 必须建表时写死

`aggregation` 取值 `each_period` / `mean` / `latest`，决定"用哪个数去比阈值"。

**这是最容易被事后操纵的一个字段**：如果允许事后选，一条 claim 不通过就换成"用平均值"再试，直到通过为止。所以规定**建表时写死，执行中不得修改**。

**实例**：案例二 C2「2025 年分派率不低于 4.81%」，`aggregation = latest`（全年值），不能用四个季度分派率的均值——因为招募书预测的是年度值，比的对象必须也是年度值。

## 六、这 24 条的共同逻辑

1. **空值零容忍，但允许"显式的不知道"**——五态空值 + 七态裁决，把"没数"和"抄漏"分开。
2. **规范先写下来，再校验**——T-DQ-05 的教训是：规范不在文档里，测试就只能校验测试作者的想法。
3. **不可比就说不可比，不硬换算**——T-DQ-07 宁愿放弃跨基金比较，也不制造虚假可比。
4. **防事后操纵**——`aggregation` 建表时写死，是流程设计上对"选择性报告"的防御。

## 七、本组未能覆盖的部分

- 面板只覆盖两只基金（508056、180302），案例三走投前路径没有季度面板；
- 未做跨基金的指标口径一致性校验（如两只仓储物流 REIT 的"出租率"分母是否都按可租面积），样本量不足；
- 锚点校验只验证"字段非空"，未验证"页码是否真的指向正确内容"——后者需要人工抽检，脚本做不了。
