  - reits-pre-investment-analysis

## report_input_contract

上游必须交付的 5 类产物。缺一项则 `#1` 判定 `BLOCKED`，不得进入写作。

| id | 产物 | 必备内容 | 缺失后果 |
|---|---|---|---|
| `IN-1` | 事实底稿 | 每个数字带 `文件 + 页码` 锚点；分 `历史事实 / 文件预测 / 独立假设` 三类 | 正文无法写锚点，全部结论降级 |
| `IN-2` | 现金流模型 | 参数与公式分离；可改参数重算；含三情景 | 第六章无法写，第八章 IRR 不可复核 |
| `IN-3` | 假设登记表 | 每条含 `取值 / 依据 / 来源 / 敏感性 / 状态` | 正文无法区分假设与事实 |
| `IN-4` | claim 裁决表 | 每条含 `aggregation / threshold / observed / verdict / evidence_ref` | 结论句无出处 |
| `IN-5` | 来源索引 | 每条含 `文件名 / 类型 / 日期 / 页数 / URL / 本地路径 / 状态` | 附录无法生成，读者无法回查 |

## outline_schema

两套骨架，按报告类型选用。**章节编号是给读者的，不是给流程的**——不得出现"数据基础与口径声明"这类工序名。

### 投前投资分析报告（`pre`）

| 序 | 章节 | 必须回答的问题 | 建议字数 |
|---|---|---|---|

| 1 | 投资摘要与核心投资判断 | 这是什么产品／买的是什么／赚钱靠什么／分派可持续吗／发行价贵不贵／最大的风险是什么／买不买 | 2,200–2,800 |

## section_contract

每节写作时逐条自检。**`question` 一栏是这一节的唯一目的**，写不出来就说明这节该删或该并。

| 字段 | 必填 | 说明 |
|---|---|---|
| `section_id` | 是 | 与 `outline_schema` 对应 |
| `question` | 是 | 一句话，必须是疑问句 |
| `claim` | 是 | 本节要证明的判断，一句话 |
| `evidence` | 是 | 支撑该判断的事实、数字或条款，带来源锚点；数量按问题决定 |
| `counter` | 否 | 重要判断的不利证据或替代解释；无充分反证时说明材料限制 |
| `implication` | 是 | 对投资判断的含义，一句话 |
| `min_words` | 否 | 仅作篇幅分配建议，不作为机械失败条件 |
| `figures` | 否 | 本节需要的图表编号 |

## style_rules

| id | 规则 | 判据（可机检） |
|---|---|---|
| `S-1` | 结论先行：每节第一段第一句必须是判断句，不是背景句 | 首段首句不含"随着""近年来""作为"开头 |
| `S-2` | 标题清晰：证据充分时可用判断式标题，说明性章节可用准确的描述式标题 | 人工检查 |
| `S-3` | 段落围绕一个问题，长度服从可读性 | 人工检查，非机械失败 |
| `S-4` | 关键数字带口径、期间和来源锚点 | 人工抽查 |
| `S-5` | 历史事实、文件预测和独立假设明确区分 | 表格表头或行标注类型 |
| `S-6` | 图表服务于论证，并注明资料来源和自算属性 | 人工检查 |
| `S-7` | 正文用自然语言表达证据确定性，不展示内部状态码 | 正文不出现状态码 |
| `S-8` | 语言直接克制，避免空泛和重复 | 人工检查 |
| `S-9` | 正文不展开内部运行和修订过程 | 禁用词表 |
| `S-10` | 风险必带传导链：机制 → 证据 → 触发条件 → 财务影响 → 监测指标 | 五要素齐全 |

## banned_patterns

正文出现任一即判 `FAIL`。附录不受限。

| 类别 | 模式 | 例 |
|---|---|---|
| 流程编号 | `FLOW #\d+`、`§\d+\.\d+（FLOW`、`Step \d` | "资产清单与权属（FLOW #8）" |
| 状态码 | `CONFIRMED`、`PARTIALLY_SUPPORTED`、`INDETERMINATE`、`NOT_COMPARABLE`、`SOURCE_UNAVAILABLE`、`DATA_QUALITY_WARNING`、`UNDEFINED_THRESHOLD` | "估值判断 `PARTIALLY_SUPPORTED`" |
| 测试语 | `PASS`、`FAIL`、`断言`、`自检通过` | "三类型数字是否混列 PASS" |
| 内部标尺 | `bands \d+/\d+`、`阈值档位`、`低位（bands` | "中位（bands 95/90）" |
| 修订语 | `初稿`、`本版`、`上一版`、`修订说明`、`更正清单` | "初稿把 DT51 当作……" |
| 运行语 | `run_log`、`执行 skill`、`按 FLOW 执行`、`产出物` | "执行 skill v1.0.0" |
| 元话语 | `本报告的处理是`、`需要说明的是`、`必须指出`（连用 ≥3 次/节） | — |

## figure_table_policy

| 项 | 规则 |
|---|---|
| 编号 | `表 1`／`图 1`，全文连续，不按章重排 |
| 标题位置 | 表在上、图在下；标题在图表**上方** |
| 资料来源 | 每张必写，格式 `资料来源：{披露文件}、{数据库}、本报告整理` |
| 自算图表 | 资料源须写"本报告整理"，不得伪装成披露数据 |
| 数据表上限 | 无固定行数；按可读性拆分，核心测算不得因行数移出正文 |
| 禁止 | 只罗列字段的"机械表"（如把招募书的产品要素表原样搬入正文）——这类表移附录 |

## word_count_policy

| 项 | 定义 |
|---|---|
| 计数对象 | 中文字符（`[\u4e00-\u9fff]`） |
| 计入 | 正文第 1–10 章（投前）／第 1–7 章（投后），含正文内表格中的分析性文字 |
| 不计入 | 封面、目录、附录、参考文献、来源索引、运行日志、自检表、版本变更记录 |
| 分别报告 | 中文正文字符数／英文字母数／数字字符数／Markdown 总字符数，四项分开，不得合并称"字数" |
| 投前下限 | **≥15,000** 中文正文；无上限，按证据和论证需要展开 |
| 投后下限 | ≥3,000 中文正文（不设上限） |
| 反注水 | 连续 30 字以上与另一段完全重复即判重复；同一表格出现两次即判重复 |
| 工具 | `python tools/count_report_words.py <report.md>` |

## review_checklist

### 第一轮：内容与逻辑（`R1`）

| id | 检查项 | 不通过示例 |
|---|---|---|
| `R1-1` | 重要结论有相称的事实、数字或条款支撑 | "资产质量优秀"无证据 |
| `R1-2` | 重要判断考虑不利证据或替代解释，无法取得时说明限制 | 只写优点 |
| `R1-3` | 收入 → EBITDA → 可供分配的传导有量化 | "成本控制良好"无数 |
| `R1-4` | 估值参数被独立评价，不是照抄 | "折现率 5%，合理" |
| `R1-5` | 分派率与 IRR 分开表述，且给出计算过程 | 只给结果 2.67% |
| `R1-6` | 情景含悲观，且悲观情景有触发路径 | 只做中性 |
| `R1-7` | 缺失资料如实标注并说明证据等级下降 | 假装已核验 |
| `R1-8` | 假设与披露不混 | 把 3.5% capex 写成"披露的 capex" |

### 第二轮：结构与表达（`R2`）

| id | 检查项 | 不通过示例 |
|---|---|---|
| `R2-1` | 全文无 `banned_patterns` 命中 | 出现 `FLOW #8` |
| `R2-2` | 标题准确反映章节内容，重要章节可体现判断 | 标题与正文不符 |
| `R2-3` | 摘要能独立成立（不读后文也能懂结论） | 摘要依赖后文才能理解 |
| `R2-4` | 无无意义的跨章重复 | 同一论证机械重复 |
| `R2-5` | 必要图表有资料来源，核心测算清楚 | 图表无法解释或无来源 |
| `R2-6` | 段落长度和表格布局便于阅读 | 长段或表格影响理解 |
| `R2-7` | 正文中文 ≥ 下限，且无 30 字重复 | 靠附录堆字数 |
| `R2-8` | 术语一致（同一指标全文一个叫法） | "有效租金"与"实收租金"混用 |

## quality_states

沿用上游七态，但**只允许出现在附录**。正文使用对应的自然语言：

| 状态码 | 正文表述 |
|---|---|
| `CONFIRMED` | 已证实／可以确认 |
| `PARTIALLY_SUPPORTED` | 方向可确认，细节证据不足 |
| `INDETERMINATE` | 现有材料无法判断 |
| `NOT_COMPARABLE` | 口径不同，不可直接比较 |
| `SOURCE_UNAVAILABLE` | 该材料未公开披露 |
| `DATA_QUALITY_WARNING` | 披露口径存在问题 |
| `UNDEFINED_THRESHOLD` | 缺少可参照的阈值 |

## versioning_rule

- 报告版本号与 skill 版本号分开记：报告 `v1.0` 起，skill `1.0.0` 起。
- 报告每轮实质修订升 `v0.x`，交付版升 `v1.0`；**版本变更记录只在附录**。
- skill 的文风规则变更须同步更新 `template/report_style_analysis.md` 的统计出处，否则规则无据。
