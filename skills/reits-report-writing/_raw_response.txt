# 公募 REITs 研究报告写作

本 skill 是一个 flow（可执行写作流程），**处在取数层的下游**。

**它解决的是一个问题**：上游研究 FLOW 跑完之后，手上有一堆正确的数字、一个可重算的模型、一张假设表，但写出来的东西读起来像运行日志。原因是**取数流程的骨架（Step 0 → 分层 → 归因 → 测算 → 估值 → 结论）与投研报告的骨架（投资问题 → 论证 → 判断）不是同一个东西**。把 FLOW 的步骤名当章节名，就等于把工序单交给了客户。

**执行方式**：阅读同目录下的 FLOW.md，按 `#1 → #13` 顺序执行。来源、计算、逻辑与表达核验并入 `#10`、`#12` 的现有检查，不要求分轮审稿，不产出独立 review 文件。步骤用于保证证据、测算和表达完整，不把案例模板或形式配额当成跨项目硬规则。

**运行前检查**：
1. 核验上游 FLOW 的事实底稿、模型、假设登记、claim 裁决和来源索引，可接受内容等价的底稿。按缺口对判断的影响处理：非核心资料缺失时注明限制并继续可支持的写作；核心证据缺失时先回上游补证，无法补齐则限定受影响结论并标注部分完成。影响投资判断的证据边界必须进入正文，不得以文字掩盖缺失，也不因单个文件缺失机械阻断全部写作。
2. 报告里的每一个数字必须能在上游产物里找到，**不允许在写作阶段新造数字**。需要新数字时，退回上游算，不许在正文里"估一个"。
3. 结论先于文字。`#2` 的论点树没定下来之前，不写任何一段正文。

**输出位置**：上游约定的 `outputs/{case}/`，文件名沿用既有命名（`report_{code}.md`）。同时产出 `report_metrics.json`（字数、图表数、禁用词命中数），供自动化测试读取。

## 这个 skill 回答什么

**不是"怎么把话说完整"，是"怎么让一个没读过原始材料的人，在 15 分钟内做出买或不买的判断"。**

所以必须做到三件事，缺一不算完成：

1. **结论在前，且是判断不是描述。** 第一章读完必须知道：这是什么、赚什么钱、值不值、什么情况下不值。
2. **每一节回答一个投资问题。** 标题准确说明本节内容；证据充分时使用判断式标题，法律、交易结构和测算章节可使用描述式标题，不为标题强造因果结论。
3. **正文保留判断所需的证据与计算。** 参数依据、口径差异、关键数据缺口及其对结论的影响进入正文；流程自检、纠错留痕和完整登记表放入附录。

## 三条硬约束

- **正文不出现流程编号与状态码。** `FLOW #n`、`run_log`、`PASS/FAIL`、`CONFIRMED`、`bands 95/90` 一律不得进入正文，只能出现在附录的执行记录或 claim 表里。
- **不写"我做了什么"，只写"事实是什么、意味着什么"。** "本报告的处理是双列并行" → "两个口径都保留：判断收现能力用四季加总，判断全年现金生成用年报数"。
- **不注水。** 字数不够时补的是**论证**（机制、反证、敏感性、可比对照），不是形容词与重复。判据：新增的每一段，删掉之后结论会变弱——如果删掉结论不变，那段是水。

## 与上游 FLOW 的接口

| 上游产出 | 本 skill 的用法 | 不得做的事 |
|---|---|---|
| `source_index.csv` + 页码锚点 | 正文数字的原始证据入口；`assumptions.csv` 区分研究假设 | 不把来源索引误当事实表，不在正文里新造数字 |
| `models/cash_flow_model.xlsx` | 情景与敏感性的数来自这里 | 不在正文里手改模型结果 |
| `assumptions.csv` | 每条假设进附录登记表；正文引用时标注"假设" | 不把假设写成"披露" |
| `claims_verdict.csv` | 裁决结果进正文的结论句，`claim_id` 与状态码进附录 | 不在正文里展示 `claim_id` |
| `source_index.csv` | 附录的来源索引；正文用"文件 + 页码"锚点 | 不用"据披露"这类无锚点表述 |

## 学谁的行文

本 skill 的文风规则基于对 11 份卖方行业深度报告的结构统计（共 408 页、327 张图表）。原始研报未随仓库提交，保留的统计口径和方法记录见 `template/report_style_analysis.md`。主要可迁移的四条：

1. **投资摘要先给判断**：概括产品、现金流、估值、主要风险和价格条件，条数按材料复杂度决定。
2. **标题帮助读者定位**：证据充分时可用判断式标题，但法律、结构和测算章节可使用准确的描述式标题。
3. **图表服务于论证**：按结构、现金流和情景分析需要配置，注明资料来源和自算属性，不设置固定密度。
4. **语言直接克制**：区分事实、预测、假设和判断，避免空泛重复，不以固定词频替代内容审查。

统计口径与原始记录见 `template/report_style_analysis.md`。

## report_input_contract

核验上游以下 5 类研究内容，允许由等价底稿承载，不以文件是否单独存在判定能否写作。非核心资料缺失时明确降级并继续可支持部分；核心证据缺失时先补证，无法补齐则限制受影响结论并标注部分完成。缺口、受影响判断和证据边界须进入正文，完整缺口登记留附录，不机械全阻断，也不把资料缺失写成已核验。

| id | 产物 | 必备内容 | 缺失处理 |
|---|---|---|---|
| `IN-1` | 事实底稿 | 关键数字带 `文件 + 页码` 锚点；分 `历史事实 / 文件预测 / 独立假设` 三类 | 无法追溯的事实不得作为确定结论依据；限定受影响判断 |
| `IN-2` | 现金流模型 | 参数与公式分离；可改参数重算；情景覆盖主要风险 | 无法复算的现金流、估值或回报不得报作已验证结果；说明不可测范围 |
| `IN-3` | 假设登记表 | 每条含 `取值 / 依据 / 来源 / 敏感性 / 状态` | 可从等价底稿补登记；无法确认的参数不得混写为披露事实 |
| `IN-4` | claim 裁决表 | 每条含 `aggregation / threshold / observed / verdict / evidence_ref` | 可沿用等价结论证据；缺少支撑的判断降低确定性或保留为不可判定 |
| `IN-5` | 来源索引 | 每条含 `文件名 / 类型 / 日期 / 页数 / URL / 本地路径 / 状态`，不适用项注明 | 可由已有原文锚点补索引；不可回查的关键证据限制相应结论 |

## outline_schema

两套写作层独立骨架，按报告类型选用，不套用取数层 METADATA 的指标 schema。**章节编号是给读者的，不是给流程的**——章节按投资问题组织；影响判断的口径、参数和证据限制须进入相应正文，不以工序名替代分析。下列章节字数区间仅为早期篇幅分配建议，不是上下限或逐章验收配额；投前中文正文合计至少 15,000 字且无上限，投后按任务和论证需要展开。

## section_contract

每节写作时逐条自检。**`question` 一栏是这一节的唯一目的**，写不出来就说明这节该删或该并。

| 字段 | 必填 | 说明 |
|---|---|---|
| `section_id` | 是 | 与 `outline_schema` 对应 |
| `question` | 是 | 一句话，必须是疑问句 |
| `claim` | 是 | 本节要证明的判断，一句话 |
| `evidence` | 是 | 支撑该判断的事实、数字或条款，带来源锚点；数量按问题决定 |
| `counter` | 否 | 重要判断的不利证据或替代解释；无充分反证时说明材料限制 |
| `implication` | 是 | 对投资判断的含义，一句话 |
| `min_words` | 否 | 仅作篇幅分配建议，不作为机械失败条件 |
| `figures` | 否 | 本节需要的图表编号 |

## banned_patterns

正文出现任一即判 `FAIL`。附录不受限。

| 类别 | 模式 | 例 |
|---|---|---|
| 流程编号 | `FLOW #\d+`、`§\d+\.\d+（FLOW`、`Step \d` | "资产清单与权属（FLOW #8）" |
| 状态码 | `CONFIRMED`、`PARTIALLY_SUPPORTED`、`INDETERMINATE`、`NOT_COMPARABLE`、`SOURCE_UNAVAILABLE`、`DATA_QUALITY_WARNING`、`UNDEFINED_THRESHOLD` | "估值判断 `PARTIALLY_SUPPORTED`" |
| 测试语 | `PASS`、`FAIL`、`断言`、`自检通过` | "三类型数字是否混列 PASS" |
| 内部标尺 | `bands \d+/\d+`、`阈值档位`、`低位（bands` | "中位（bands 95/90）" |
| 修订语 | `初稿`、`本版`、`上一版`、`修订说明`、`更正清单` | "初稿把 DT51 当作……" |
| 运行语 | `run_log`、`执行 skill`、`按 FLOW 执行`、`产出物` | "执行 skill v1.0.0" |

元话语如“需要说明的是”仅作人工清理提示，不以固定词频判失败；必要的方法说明和证据边界应保留。

## figure_table_policy

| 项 | 规则 |
|---|---|
| 编号 | `表 1`／`图 1`，全文连续，不按章重排 |
| 标题位置 | 表题与图题均在对应图表上方，资料来源置于下方 |
| 资料来源 | 每张必写，格式 `资料来源：{披露文件}、{数据库}、本报告整理` |
| 自算图表 | 资料源须写"本报告整理"，不得伪装成披露数据 |
| 数据表上限 | 无固定行数；按可读性拆分，核心测算不得因行数移出正文 |
| 禁止 | 只罗列字段的"机械表"（如把招募书的产品要素表原样搬入正文）——这类表移附录 |

## word_count_policy

| 项 | 定义 |
|---|---|

| 反注水 | 连续 30 字以上与另一段完全重复即判重复；同一表格出现两次即判重复 |
| 工具 | `python tools/count_report_words.py <report.md>` |

## review_checklist

在既有结构及数字核验步骤中使用以下清单，发现问题直接修正报告；不要求固定轮次或独立 review 文件。

### 内容与逻辑

| id | 检查项 | 不通过示例 |
|---|---|---|
| `C-1` | 重要结论有相称的事实、数字或条款支撑 | "资产质量优秀"无证据 |
| `C-2` | 重要判断考虑不利证据或替代解释，无法取得时说明限制 | 只写优点 |
| `C-3` | 收入 → EBITDA → 可供分配的传导有量化 | "成本控制良好"无数 |
| `C-4` | 估值参数被独立评价，不是照抄 | "折现率 5%，合理" |
| `C-5` | 分派率与 IRR 分开表述，且给出计算过程 | 只给结果 2.67% |
| `C-6` | 情景含悲观，且悲观情景有触发路径 | 只做中性 |
| `C-7` | 缺失资料如实标注并说明证据等级下降 | 假装已核验 |
| `C-8` | 假设与披露不混 | 把 3.5% capex 写成"披露的 capex" |

### 结构与表达

| id | 检查项 | 不通过示例 |
|---|---|---|
| `E-1` | 全文无 `banned_patterns` 命中 | 出现 `FLOW #8` |
| `E-2` | 标题准确反映章节内容，重要章节可体现判断 | 标题与正文不符 |
| `E-3` | 摘要能独立成立（不读后文也能懂结论） | 摘要依赖后文才能理解 |
| `E-4` | 无无意义的跨章重复 | 同一论证机械重复 |
| `E-5` | 必要图表有资料来源，核心测算清楚 | 图表无法解释或无来源 |
| `E-6` | 段落长度和表格布局便于阅读 | 长段或表格影响理解 |
| `E-7` | 正文中文 ≥ 下限，且无 30 字重复 | 靠附录堆字数 |
| `E-8` | 术语一致（同一指标全文一个叫法） | "有效租金"与"实收租金"混用 |

## quality_states

沿用上游七态，但**只允许出现在附录**。正文使用对应的自然语言：

| 状态码 | 正文表述 |
|---|---|
| `CONFIRMED` | 已证实／可以确认 |

| `NOT_COMPARABLE` | 口径不同，不可直接比较 |
| `SOURCE_UNAVAILABLE` | 该材料未公开披露 |
| `DATA_QUALITY_WARNING` | 披露口径存在问题 |
| `UNDEFINED_THRESHOLD` | 缺少可参照的阈值 |
