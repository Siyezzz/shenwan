# 公募 REITs 研究报告写作

本 skill 是一个 flow（可执行写作流程），**处在取数层的下游**。

**它解决的是一个问题**：上游研究 FLOW 跑完之后，手上有一堆正确的数字、一个可重算的模型、一张假设表，但写出来的东西读起来像运行日志。原因是**取数流程的骨架（Step 0 → 分层 → 归因 → 测算 → 估值 → 结论）与投研报告的骨架（投资问题 → 论证 → 判断）不是同一个东西**。把 FLOW 的步骤名当章节名，就等于把工序单交给了客户。

**执行方式**：阅读同目录下的 FLOW.md，按 `#1 → #14` 顺序执行。来源、计算、逻辑与表达核验并入 `#10`、`#12` 的现有检查，不要求分轮审稿，不产出独立 review 文件。步骤用于保证证据、测算和表达完整，不把案例模板或形式配额当成跨项目硬规则。

**成稿范式**：投后跟踪报告的版式与句式写在下文《成稿范式：投后跟踪报告》一节——封面八行元信息、`职能短语：本期判断` 式标题、加粗判断句三段式、图表四行式（含差额）、自算与披露不符的四步交代法、跨期表述对照、摘要五段、附录五段、成稿六问。`#4`（定标题）、`#5`（写摘要）、`#7`（标口径）、`#8`（配图表）、`#11`（复核结构）按该节执行；版面几何、配色与字体在 `METADATA.md` 的 `visual_style`，可机检的硬项在 `style_rules` 的 `S-11`—`S-16`。投前与横向基准只借用其中可迁移的部分（标题命名、四步交代法、差额说明、自检六问），不套用投后的章节与附录结构。

**运行前检查**：
1. 核验上游的事实底稿、模型、假设登记、claim 裁决和来源索引，可接受内容等价的底稿。横向基准报告核验 `findings.csv`：每行的判断、用词档位、证据锚点、反例是否齐备。按缺口对判断的影响处理：非核心资料缺失时注明限制并继续可支持的写作；核心证据缺失时先回上游补证，无法补齐则限定受影响结论并标注部分完成。证据边界必须进入正文，不得以文字掩盖缺失，也不因单个文件缺失机械阻断全部写作。
2. 报告里的每一个数字必须能在上游产物里找到，**不允许在写作阶段新造数字**。需要新数字时，退回上游算，不许在正文里"估一个"。
3. 结论先于文字。`#2` 的论点树没定下来之前，不写任何一段正文。
4. **判断的档位也不许改。** 上游标"组内排序"的，正文只能写位次与幅度；要升级用词，退回上游补绝对锚。

**输出位置**：上游约定的 `outputs/{case}/`，文件名沿用既有命名（`report_{code}.md`）。同时产出 `report_metrics.json`（字数、图表数、禁用词命中数），供自动化测试读取。阅读版 `.html` 用 `python tools/render_report.py <report.md>` 生成（图 base64 内嵌、零依赖，几何与配色见 `METADATA.md` 的 `visual_style`），不手写 CSS、不手改 html。

## 这个 skill 回答什么

**不是"怎么把话说完整"，是"怎么让一个没读过原始材料的人，在 15 分钟内看懂这笔资产的处境"。**

两类报告的目标不同：

- **投前分析**：读完要知道——这是什么、赚什么钱、值不值、什么情况下不值；
- **横向基准**：读完要知道——它在同类里是什么位置、这个位置靠什么撑着、哪句话会被下一期数据改写。这类报告**不给买或不买的结论**，所以它的"有用"体现在坐标、幅度与可证伪条件上，不体现在评级上。

两类的共同要求是三条，缺一不算完成：

1. **结论在前，且是判断不是描述。**
2. **每一节回答一个问题。** 标题准确说明本节内容；证据充分时使用判断式标题，法律、交易结构与测算章节可用描述式标题，不为标题强造因果。
3. **正文保留判断所需的证据与计算。** 参数依据、口径差异、关键缺口及其对结论的影响进入正文；流程自检、纠错留痕与完整登记表放入附录。

## 记者视角：你是记者，不是模型

模型的写法是"本报告如何处理这些数据"；记者的写法是"谁在什么时候因为什么多赚或少赚了多少钱"。**读者关心的从来不是你的流程，是那笔钱。**

判断一段是否合格，只问一句：**把这段话念给一个没看过材料的人听，他能不能说出"谁受损、谁受益、大概多少"？** 说不出，这段就是方法论述，删或移到附录。

### 六种必改的写法

| 病 | 反例（模型腔） | 改法（记者腔） | 为什么 |
|---|---|---|---|
| 自指 | 「本报告回答三件事：……」 | 直接给三句判断，不宣告要回答什么 | 报告不是议程，是结论。宣告"我要回答什么"占的是读者最贵的版面 |
| 邀读者核对 | 「读者可以不同意，但能看见怎么选的」「可按 §3.4 逐句核对」 | 「十只仓储 REIT 里四只进不来：三只没有完整年度数据，一只不足十万㎡」 | 把"你可以看"改成"这是事实"。请读者核对，是把责任推回去 |
| 判决交给"本报告" | 「本报告倾向第二种解释」 | 「我们倾向第二种：租金一年跌 17.45%，市场在提前定价继续下跌，不是算错了价」 | 判断要有人承担。全篇只允许"我们"承担三种事：给倾向、承认不知道、承担测算 |
| 形容词结论 | 「资产质量相对较弱」「盈利承压」 | 「出租率 89.54%，比六只中位数低 3.2pct，比第一名低 6.8pct」 | 形容词无法证伪，也无法比较。强弱必须落到数字与对手 |
| 裸数字 | 「计提减值 7,152 万元」 | 「减值 7,152 万元，相当于全年可供分配的 41%」 | 数字要有参照系：占比、相当于、比谁多多少。读者感知不到 7,152 万是什么概念 |
| 清单体 | 「第一，……。第二，……。第三，……」连着三节 | 一段一个因果，先给反常事实，再给解释 | 清单是索引，不是论证。整节都在"第一第二第三"，说明还没想清楚哪句是主句 |

### 三条可以机械执行的编辑动作

1. **换标测试。** 把句子里的标的换成另一只，若句子照样成立，这句没有信息量，删。例：「仓储物流 REIT 普遍面临租金下行压力」→ 换成任何一只都成立，属于背景，不进正文。
2. **删首段。** 每节第一段若在交代背景、定义概念、复述上一节，整段删掉，从第二段开始。第一句应当是这一节最反常的事实。
3. **删尾句。** 每节最后一句若在总结"综上所述""由此可见"，删。读者不需要被告知刚读完什么。

### 允许的例外

口径换算、取数路径、"为什么用反推市值"这类必要说明**不是废话**，但要降级到括号、图注或附录，正文最多留一句"（口径见附录）"。判断标准：删掉这句，结论是否仍成立——成立就移走，不成立才留。

## 三条硬约束

- **正文不出现流程编号与状态码。** `FLOW #n`、`run_log`、`PASS/FAIL`、`CONFIRMED`、`bands 95/90` 一律不得进入正文，只能出现在附录的执行记录或 claim 表里。
- **不写"我做了什么"，只写"事实是什么、意味着什么"。** "本报告的处理是双列并行" → "两个口径都保留：判断收现能力用四季加总，判断全年现金生成用年报数"。
- **不注水。** 字数不够时补的是**论证**（机制、反证、敏感性、可比对照），不是形容词与重复。判据：新增的每一段，删掉之后结论会变弱——如果删掉结论不变，那段是水。

## 成稿范式：投后跟踪报告

`outline_schema.post` 管"写哪几章"，`style_rules` 管"语言什么调性"，本节管**同样的内容怎么排布才读得下去**。它是版式与句式，不是形式配额；某条与具体标的冲突时以内容需要为准，但删掉要能说出理由。

### 封面：一行标题 + 八行元信息

```markdown
# 基金全称（代码）YYYY 年第 N 季度投后跟踪

| 项 | 内容 |
|---|---|
| 基金全称 |  |
| 基金代码 |  |
| 跟踪区间 | 2025Q1–2026Q3，重点期 2025Q4 |
| 重点期截止日 | 2025 年 12 月 31 日 |
| 数据截止日 | 2026 年 10 月 27 日（2026 年第 3 季度报告披露日） |
| 版本 | v1.0 |
| 正文篇幅 | N 个中文字符（第 1—7 章，不含附录与图表） |
| 资料完整性 | 季度报告 N 份、年度报告 N 份、中期报告 N 份、招募说明书 N 版、评估与审计文件 N 份；M 份早期文件无文字层，K 份仅有文本副本，两类均已登记，不参与本期取数 |
```

三条硬要求：

- **`跟踪区间` 与 `重点期` 分两行写。** 序列拉到哪一期（看趋势）和这一期重点分析哪一季（给结论）是两件事。合成一个"分析区间"会让读者以为结论覆盖整个区间。
- **`数据截止日` 带括号说明依据。** 写"2026-10-27"没有信息量，写"2026 年第 3 季度报告披露日"才说明白为什么停在这里。
- **`资料完整性` 不是装饰。** 它要写清两件事：手上有几份、哪几份**不能用**。不能用的必须显式说明原因（无文字层／仅文本副本／未披露），并写明"不参与本期取数"。这一行是全部结论的证据边界声明。

### 章节标题：冒号前给位置，冒号后给本期事实

投后七章不用"运营表现""项目归因"这种工序名。范式是 **`职能短语：本期判断`**：

| 类型 | 例 | 结构 |
|---|---|---|
| 三元并列 | 运营表现：量回升、价下行、期限缩短 | 三个方向各一个动词短语，直接给三维走向 |
| 双主体对撞 | 项目归因：两个园区撑起增幅，三个园区拖累 | 谁贡献、谁拖累，用数量代替形容 |
| 反转 | 收入与可供分配：跌得更快的是分配，不是收入 | 否定读者的默认预期 |
| 转折 | 投资含义：分派还在，但来源在变 | 承认一侧、否定另一侧 |

**自检问句**：把标题里的本期事实换成上一期，句子还成立吗？成立就说明这句是背景、不是判断，重写冒号后的部分。"运营表现：量、价、期限三个维度各往哪走"这类也不合格——它是问题，不是答案，问题属于 `section_contract.question`。

### 正文段落：加粗判断句 + 数字支撑 + 边界

一个自然段内完成三段式：

```
**判断句，≤40 字，句号结尾，含"谁 + 怎么样了"。**
第 2—4 句给数字，每个数字紧跟参照系（占比／相当于／位次／对手比较）。
末句给边界：什么没披露、差从哪来、为什么不可判定。
```

实样：

> **江门鹤山是最大拖累，且原因未披露。** 出租率从 90.02% 降至 64.59%，降 25.43 个百分点，权重 10.71%，单项拖累 −2.722 个百分点（q2025Q4 p13、q2024Q4 p25）。64.59% 是十园最低值，比第二名淀山湖（73.15%）低 8.56 个百分点。季报与年报均未单列退租面积、退租租户或去化计划，这一项的成因不可判定。

判断句必须能单独抽出来当结论用。三种不合格开头：`从运营数据来看……`／`就项目层面而言……`（空转，没说事）；`本季度出租率有所下降`（"有所"是回避幅度）；超过 40 字、带两个以上逗号（判断被稀释）。

**参照系只允许四类**：占比（占收入 82.5%）、相当于（相当于 0.67 个淀山湖）、位次（8 季中位、第 5/8）、对手比较（比第二名低 8.56pct）。四类都写不出来，说明这个数字不该进正文。

### 图：四行式，且必须写差额

```markdown
![图 N 短标题](figures/figN_xxx.png)

图 N 完整标题（含期间与口径）
资料来源：文件简称 页码；招募说明书 YYYY 版 p—p；整理（自算）
口径说明：定义式、取值范围、与披露值的差额及原因
```

关键在第四行。多数报告写到"资料来源"就停，这不够——**口径说明要给出这张图与披露数字差多少、为什么差**：

> 口径说明：贡献 = 面积权重 × 出租率变动；面积权重按 2022-12-31 基准面积计算，合计贡献 +2.981 个百分点，与披露 +3.17 个百分点差 0.19 个百分点。

图内嵌在**它所支撑的那个论证段之后**，不出现"图见附件"或"如图 N 所示"先行指路。短标题（alt）给目录用，完整标题给读者用。

### 表：先结论、后表格、再三行说明

顺序不可颠倒：**论证段 → 表题 → 表格 → 资料来源 → 口径说明**。表题位置按 `figure_table_policy`（在上方），全篇统一，不得一半在上、一半在下。宽表四条：

- 首列是名称列、左对齐；数值列右对齐。
- 差额列用 `+` / `−` 显式带符号，不带符号的"变动（pct）"列会被读成绝对值。
- 缺失值写 `未披露`，不留空、不写 `N/A`、不写 `—`；空单元格会被误认为 0。
- 合计行写 `合计 / 加权`，并让合计值能与披露值并列比较。

### 自算值与披露值不一致：四步交代法

投后报告最容易被抓的地方，是自己算的数和披露的数不一样。范式是**不藏、不取整、不选边**：给自算值 → 给披露值 → 量化差额 → 把差额归到具体口径差异上。

> 按项目可租赁面积加权，2025 年第四季度出租率同比变动可分解为十个园区的贡献之和 +2.981 个百分点，与披露的组合同比 +3.17 个百分点差 0.19 个百分点，差异来自面积口径——分解用招募说明书 2026 版第 270—271 页的 2022 年 12 月 31 日基准面积，合计 1,163,212.20 平方米，与季报期末可供出租面积一致，但个别园区（空港 128,060.52 平方米对季报 128,061.00 平方米）有 0.48 平方米的四舍五入差。

三种不合格处理：只写"基本一致"（不给数就不叫交代）；把自算值改成披露值（分解表行加总与合计行对不上）；两个都写但不解释差（读者会怀疑算术）。差额归不到具体原因时，明写"差额未在披露中定位"，不要编一个口径。

### 跨期表述对照：上年怎么说，一年后怎么样

投后独有、也是最能体现跟踪价值的一种段落，三句结构：引上年同期原文（带页码，逐字或用「」标出）→ 给一年后实际数字 → 判断能否归因（能就归因，不能就写"只能记录方向相反这一事实"）。

> **上年同期对两个园区的表述与一年后的结果方向相反。** 2024 年第四季度季报对江门鹤山的表述为「与新增租户签订长期租约，本期内出租率稳步提升，园区运营稳定性有望逐步增强」；对淀山湖的表述为「累计已完成 133,396.36 平方米替换租户的签约……若后续顺利完成签约，该园区剩余面积有望全部实现去化」。2025 年第四季度实际为江门 64.59%（同比 −25.43 个百分点）、淀山湖 73.15%（同比 −9.25 个百分点）。两处表述均未给出量化去化目标与时间表，因此无法据以判断是执行不力还是市场变化，只能记录方向相反这一事实。

纪律：**陈述、不评价**。不写"管理层失信""承诺落空"，落点放在"表述未含量化目标，因此不可归因"。同一手法用于识别**披露文字与指标读数冲突**：季报正文写"环比保持平稳"、指标是 −2.82 个百分点，就照实并列，并写明"披露文字对短期波动的描述不能替代指标读数"。

### 结论摘要：五段，每段一个判断

不写"本报告分为几部分"，按五个问题各一段：

| 段 | 回答 | 实样首句 |
|---|---|---|
| 1 | 这一季整体是什么 | 2025 年第四季度是量升价跌的一季 |
| 2 | 哪两个数互相矛盾，拆开是什么 | 出租率涨了，收入没跟上 |
| 3 | 分配端怎样，和上期比 | 可供分配金额 8,664.92 万元，同比减 6.62% |
| 4 | 哪个好看的数其实是假象 | 高分派率是当季费用时点配合，不是趋势 |
| 5 | 最该盯哪一项 | 最需要盯的是租期 |

第 4 段是摘要的成败所在：**必须找出一个"看起来好、实际不可持续"的指标并当场拆掉**——高分派率、收缴率破百、出租率反弹都属于这一类。没有这一段，摘要只是把季报又念了一遍。摘要段落不加粗（加粗留给正文），但每段首句就是判断句，只读每段第一句也能得到完整结论。

### 附录：五段

| 段 | 内容 | 形式 |
|---|---|---|
| A.1 口径说明 | 单季与累计、价格口径切换、分派与可供分配的差别、分派率分母 | 两列表：项 / 处理 |
| A.2 数据质量 | 原件互相矛盾、口径断点、四季加总与年报差额 | 五列表：期间 / 指标 / 问题 / 处理 / 标记 |
| A.3 不可判定清单 | 每条给"缺什么 + 因此哪个结论不成立" | 编号列表，每条一句半 |
| A.4 来源索引与图表清单 | 索引表字段说明 + 图清单 + 表清单 | 一段说明 + 两张三列表 |
| A.5 执行记录 | 取数顺序、文件核对结论、面板校验、对账闭合 | 一段散文，用分号连 |

A.2 与 A.3 的分界：**A.2 是"数有问题"，A.3 是"结论做不了"**。四季加总算不出年报数属 A.2；招募书没给当年预测值、导致达成率不可计算属 A.3。A.3 每条必须写清缺口的**后果**，不能只写"未披露"——读者要由此知道这个指标本期作废，而不是"再找找就有"。A.5 只写**做了哪些核对、结果如何**，不写工具名、脚本名、重试过程，它是给复核者的对账线索，不是施工日志。

### 成稿六问

成稿后逐条过，任一条答"否"就回去改：

1. 封面「资料完整性」是否说明了哪几份文件不能用、为什么？
2. 七个章节标题，把本期事实换掉后是否**不再成立**？
3. 每个正文自然段的首句能否单独抽出来当结论？有没有"从……来看"式空转？
4. 每张图、每张表的「口径说明」是否写了与披露值的差额及原因？
5. 全文中"自算值与披露值不一致"的地方，是否都用了四步交代法？
6. 摘要第 4 段是否拆掉了一个"看起来好、实际不可持续"的指标？

各范式小节与 `METADATA.md` 机检项的对应：封面 `S-16`｜标题 `S-11`｜段落三段式 `S-12`｜图四行式与差额 `figure_table_policy`｜四步交代 `S-13`｜跨期表述对照 `S-14`｜摘要第 4 段 `S-15`｜附录五段 `outline_schema.post`。

## 与上游的接口

上游有两类：**取数层**（`reits-pre-investment-analysis`／`reits-post-investment-monitor`）交模型与底稿；**论证层**（`reits-peer-benchmarking`）交判断与档位。前者给数字，后者给结论，接法不同。

| 上游产出 | 本 skill 的用法 | 不得做的事 |
|---|---|---|
| `source_index.csv` + 页码锚点 | 正文数字的原始证据入口；`assumptions.csv` 区分研究假设 | 不把来源索引误当事实表，不在正文里新造数字 |
| `models/cash_flow_model.xlsx` | 情景与敏感性的数来自这里 | 不在正文里手改模型结果 |
| `assumptions.csv` | 每条假设进附录登记表；正文引用时标注"假设" | 不把假设写成"披露" |
| `claims_verdict.csv` | 裁决结果进正文的结论句，`claim_id` 与状态码进附录 | 不在正文里展示 `claim_id` |
| `findings.csv`（横向基准） | 一行一条判断，带**用词档位**（组内排序／相对位置／模型条件下的偏离）；正文按档位写句，不得升格 | 不把"组内排序"档写成"有吸引力"；不合并两条 finding 拼出一个更强结论 |
| `panel.csv` / `matrix_*.csv`（横向基准） | 表格与图的底数，正文数字从此处取 | 不在正文里手算新派生指标 |

**档位是硬约束，不是建议。** 上游标了"组内排序"的句子，正文只能写"组内第 3，与中位差 12bp"；要写成"高于同业"必须上游补出绝对锚。写作层没有权限补，因为这属于判断，不属于表达。

## 学谁的行文

本 skill 的文风规则基于对 11 份卖方行业深度报告的结构统计（共 408 页、327 张图表），是仓库的历史统计记录，不是本次独立复核结果。原始研报未随仓库提交，保留的统计口径和方法记录见研究仓库根目录的 `template/report_style_analysis.md`（不随本 skill 分发）。主要可迁移的四条：

1. **投资摘要先给判断**：概括产品、现金流、估值、主要风险和价格条件，条数按材料复杂度决定。
2. **标题帮助读者定位**：证据充分时可用判断式标题，但法律、结构和测算章节可使用准确的描述式标题。
3. **图表服务于论证并嵌入报告**：按结构、现金流和情景分析需要配置，放在对应论证旁，注明资料来源和自算属性，不设置固定密度。
4. **语言直接克制**：区分事实、预测、假设和判断，避免空泛重复，不以固定词频替代内容审查。

统计口径与原始记录见研究仓库根目录的 `template/report_style_analysis.md`。

**记者腔的参照不是券商深度，是财经报道的调查稿**：主语具体（某座仓库、某个租户、某个条款）、时间具体（哪一年、哪一期）、金额具体（多少、占多少）、判断有署名（谁认为、凭什么）。券商报告可以提供结构与图表规范，但它的"本公司认为""综上所述"不该出现在这里。

## report_input_contract

核验上游以下 5 类研究内容，允许由等价底稿承载，不以文件是否单独存在判定能否写作。非核心资料缺失时明确降级并继续可支持部分；核心证据缺失时先补证，无法补齐则限制受影响结论并标注部分完成。缺口、受影响判断和证据边界须进入正文，完整缺口登记留附录，不机械全阻断，也不把资料缺失写成已核验。

| id | 产物 | 必备内容 | 缺失处理 |
|---|---|---|---|
| `IN-1` | 事实底稿 | 关键数字带 `文件 + 页码` 锚点；分 `历史事实 / 文件预测 / 独立假设` 三类 | 无法追溯的事实不得作为确定结论依据；限定受影响判断 |

## reference_and_artifact_policy

- 引用文件路径均以仓库根目录为基准；运行前核对文件实际存在，外部引用须含发布主体、标题、版本/日期、完整 URL、获取日期及可回查锚点。法规仅有名称/年报仅有示例章节号时，不视为已核验依据。
- `source_index.csv` 是一行一份资料的目录（来源、日期、URL、本地副本与状态）；`panel.csv` 是一行一个指标观测值的数值表（observation_id、source_id、期间、单位、口径和页码）；`findings.csv` 是一行一条判断的论证表（证据、限定、档位和失效条件）。三者均为内部底稿，不能相互替代，也不作为默认独立成品呈现。
- 横向基准按 `skills/reits-peer-benchmarking/METADATA.md` 的 artifact_contract 关联：source_index → panel → matrix_*.csv → findings → report。追查关键结论至原件，缺键/未核实引用先修复或降级；旧索引允许用唯一 local_path 映射 source_id。
- 写作风格出处为 `template/report_style_analysis.md` 的历史统计记录（11 份/408 页/327 张图表）；原始 PDF 未随仓库提交，因此不能声称本次独立复核了这些统计。记者腔、章节骨架和其他编辑要求是内部规则，不冒充外部研究结论。
- 对阈值、案例经验和模型公式登记内部方法或外部出处；内部假设不得写成监管标准、公认健康线或已证实因果。模型计算须保留脚本/公式及输入引用。

## outline_schema

两套写作层独立骨架，按报告类型选用，不套用取数层 METADATA 的指标 schema。**章节编号是给读者的，不是给流程的**——章节按投资问题组织；影响判断的口径、参数和证据限制须进入相应正文，不以工序名替代分析。下列章节字数区间仅为早期篇幅分配建议，不是上下限或逐章验收配额；投前中文正文合计至少 15,000 字且无上限，投后按任务和论证需要展开。

### 横向基准对比报告（`comparison`）

不回答"值不值得买"，回答"在同类里是什么位置、靠什么撑着、哪句话会被下一期改写"。因此没有评级、没有目标价、没有总分。

| 序 | 章节 | 必须回答的问题 | 写作要点 |
|---|---|---|---|
| 0 | 封面 | 标的代码、比较时点、样本量、版本、字数 | 写清"比较时点"是年报口径，不是行情时点 |
| 1 | 结论与位置 | 这几只各自处在什么位置？一句话说得出来吗 | 三句话：位置、稳定性、结构性来源；附位置表（位次／幅度／锚定三列）。不写"处于中游" |
| 2 | 为什么是这几只 | 样本怎么来的，排除了谁，为什么排除 | 候选池全量枚举 → 逐条排除理由 → 边界检验一只。用户提过 ABS 的，在此交代收敛理由 |
| 3 | 时点、口径与标准 | 拿什么当标准？这些线为什么与样本无关 | 三层参照的取值与阈值、判定用词三档、五处换算。这一节是读者检验全部结论的入口 |
| 4 | 收益率：三个口径 | 换一个口径，名次还成立吗 | 三口径排名 + 名次变动幅度；逐口径过绝对锚（国债溢价）。先写名次是否稳定，再解释为什么 |
| 5 | 资产质量：四个维度 | 这个收益是靠什么换来的 | 四维位次 + 健康线 + 客户结构；给剔除租期的稳健版，说明哪些名次会翻转 |
| 6 | 收益率与质量合起来看 | 贵还是便宜，贵在哪一项 | 定价函数（斜率是一个结论）＋ 残差 ＋ 二维定位。残差三种解释分列，不写买卖信号 |
| 7 | 商业模式：风险在谁的表上 | 谁承担、上限多少、能不能换一张表 | 风险归属表 → 五轴 → 条件式优劣。不给总分，不给"最优模式" |
| 8 | 可改进处与独特优势 | 能改什么、改不动的是什么 | 可改进项四条（挂坐标＋轴＋可迁移性＋下期字段）；优势三条（唯一＋不可复制＋消失条件） |
| 9 | 下一期什么会改写结论 | 到哪一步这句话就不成立了 | 逐句给改写条件（指标＋阈值＋会改写哪一句）。可观测，不写"持续关注" |
| A | 附录 | 来源索引／口径日志／缺口清单／执行记录 | 不计入正文；状态码只允许出现在这里 |

### comparison_handoff_policy

- 写作前为每条有效 finding 建立章节映射：`finding_id → primary_section + reuse_sections`。每个章节的核心判断必须能回指 finding；每条 finding 也须标记“正文使用 / 附录限制 / 未采用及原因”，不得靠章节覆盖感代替逐条核对。
- 同一 finding 在摘要、正文、表格和图注复用时，判断方向、数值、单位、期间、证据状态、限定语与失效条件保持一致。若一个结论依赖多个 finding，登记全部依赖；不得拼接较弱 finding 形成更强判断。
- `verified / derived / assumed / unavailable / not_applicable / not_comparable` 等证据状态须转成准确自然语言。假设或推断不得写成披露事实、已证实因果或确定行动建议；派生值需保留公式与来源锚点。
- 依赖项未满足时，阻断该 finding 的强结论及其派生表述；允许写已独立成立的部分，并在正文和缺口清单标明影响范围。不得因非核心缺口机械阻断整篇报告。
- 排名样本、模式参照样本与背景参照样本分别标识；模式/背景参照不得混入统一排名、位置表、摘要结论或排名图。
- 章节标签与象限/分类结论必须来自同一张锁定的数据表或脚本输出。正文不得手工另造标签；同一标的跨表或跨章节出现冲突时，先回上游修正源表并重生成全部引用。
- 最终复核采用双向清点：逐条 finding 核对正文所有复用点；逐条核心正文判断反查 finding 与证据。旧案例章节索引、关键词出现或表格存在，不构成此项验收。

## figure_delivery_policy

- 将采用的图片与图表嵌入报告相关正文，紧邻对应论证，附图号、标题、期间、单位、来源及必要限定；不得只列图片路径或下载链接代替图片。
- 将素材目录作为内部素材目录，不默认单独呈现图片、图片卡片或图集；目录名以**上游产出为准**（投前与横向基准为 `figures/`，投后链路为 `charts/`），同一份报告内不得混用。默认向用户呈现完整报告，只有用户明确要求时才另交图片素材。
- Markdown 使用可解析的相对图片引用 `![图号与标题](figures/figN_xxx.png)`（投后链路把 `figures/` 换成 `charts/`）；SVG 等矢量源留在工作目录，交付目录只放最终位图与报告；交付时保留资源目录并打包，不能把依赖本地图片的裸 Markdown 称为独立完整报告。
- HTML 将 SVG 内联、位图转为 data URI，形成无需外部图片文件的自包含报告；若任务要求 Word/PDF，则将图片实际嵌入文档，不以外链代替。
- 维护内部图表清单：`figure_id / path / finding_ids / section_id / caption / source_anchor / disposition`；逐图登记正文采用、附录采用或未采用及原因。交付前检查所有采用图片确实出现在报告、引用可解析、图文同值且渲染可读；失败则修复或标注报告未完成，不得用单独展示图片替代。

## section_contract

每节写作时逐条自检。**`question` 一栏是这一节的唯一目的**，写不出来就说明这节该删或该并。

| 字段 | 必填 | 说明 |
|---|---|---|
| `section_id` | 是 | 与 `outline_schema` 对应 |
| `question` | 是 | 一句话，必须是疑问句 |
| `claim` | 是 | 本节要证明的判断，一句话 |
| `evidence` | 是 | 支撑该判断的事实、数字或条款，带来源锚点；数量按问题决定 |
| `counter` | 否 | 重要判断的不利证据或替代解释；无充分反证时说明材料限制 |
| `implication` | 是 | 对投资判断的含义，一句话 |
| `min_words` | 否 | 仅作篇幅分配建议，不作为机械失败条件 |
| `figures` | 否 | 本节需要的图表编号 |

## style_rules

|---|---|---|

| `S-2` | 标题清晰：证据充分时可用判断式标题，说明性章节可用准确的描述式标题 | 人工检查 |
| `S-3` | 段落围绕一个问题，长度服从可读性 | 人工检查，非机械失败 |
| `S-4` | 关键数字带口径、期间和来源锚点 | 人工抽查 |
| `S-5` | 历史事实、文件预测和独立假设明确区分 | 表格表头或行标注类型 |
| `S-6` | 图表服务于论证，并注明资料来源和自算属性 | 人工检查 |
| `S-7` | 正文用自然语言表达证据确定性，不展示内部状态码 | 正文不出现状态码 |
| `S-8` | 语言直接克制，避免空泛和重复 | 人工检查 |
| `S-9` | 正文不展开内部运行和修订过程 | 禁用词表 |
| `S-10` | 风险必带传导链：机制 → 证据 → 触发条件 → 财务影响 → 监测指标 | 五要素齐全 |
| `S-11` | 投后七章标题用 `职能短语：本期判断`（三元并列／双主体对撞／反转／转折），不用工序名 | 把标题里的本期事实换成上一期，句子仍成立即不合格 |
| `S-12` | 正文自然段三段式：加粗判断句（≤40 字）→ 数字与参照系 → 边界（未披露／差额来源／不可判定） | 首句超过 40 字或含两个以上逗号；首句以「从……来看／就……而言」开头 |
| `S-13` | 自算值与披露值不一致时走四步交代：给自算值、给披露值、量化差额、归因到口径 | 只写「基本一致」；或把自算值改成披露值；或两值并列不解释差 |

| `S-15` | 摘要五段，第 4 段必须拆掉一个「看起来好、实际不可持续」的指标 | 摘要未出现高分派率／收缴率破百／出租率反弹中任一项的拆解 |
| `S-16` | 封面八行元信息，`跟踪区间` 与 `重点期` 分列，`数据截止日` 带依据，`资料完整性` 写明哪几份不能用及原因 | 缺任一行；或 `资料完整性` 只报份数不报不可用项 |

## voice_rules（记者腔）

判断标准只有一句：**这段话念给没看过材料的人听，他能不能说出"谁受损、谁受益、大概多少"。** 说不出就是方法论述，移附录或删。`V-*` 与 `S-*` 同时适用，冲突时以 `V-*` 为准。

| id | 规则 | 反例 → 改法 | 判据 |
|---|---|---|---|
| `V-1` | 主语是人与钱，不是报告 | 「本报告回答三件事」→ 直接给三句判断 | 正文 0 次「本报告／本文／本篇」作论证主语 |
| `V-2` | 判断有人承担 | 「本报告倾向第二种」→「我们倾向第二种：租金一年跌 17.45%，市场在提前定价继续下跌」 | 「我们」每千字 ≤1 次，且只用于给倾向／承认不知道／承担测算 |
| `V-3` | 数字带参照系 | 「减值 7,152 万元」→「减值 7,152 万元，相当于全年可供分配的 41%」 | 关键数字后 12 字内出现占比、相当于或对手比较之一 |
| `V-4` | 用位次与幅度替代形容词 | 「资产质量相对较弱」→「出租率 89.54%，比中位数低 3.2pct，比第一名低 6.8pct」 | 正文无「显著／明显／较为／整体／一定程度」修饰结论 |
| `V-5` | 一段一个因果，先给反常 | 整节「第一、第二、第三」→ 一段一因，首句给这一节最反常的事实 | 单段出现三个以上并列序号即拆分 |
| `V-6` | 方法降级到括号、图注、附录 | 「本报告用可供分配÷披露分派率反推市值」→「市值按年报反推（口径见附录）」 | 正文方法句删掉后结论仍成立即移走 |
| `V-7` | 不跟读者说话 | 「读者可以不同意」「可按 §3.4 核对」→ 直接陈述事实 | 0 次「读者／可以看到／请注意／综上」 |
| `V-8` | 换标测试 | 「仓储 REIT 普遍面临租金下行压力」→ 换任何一只都成立，属背景，删 | 把标的替换为样本内另一只，句子仍成立即删 |

### editorial_actions（可机械执行）

| id | 动作 | 做法 |
|---|---|---|
| `E-A` | 换标测试 | 把句中标的全换成另一只；仍成立＝无信息量，删 |
| `E-B` | 删首段 | 每节首段若在交代背景、定义概念、复述前文，整段删，从第二段起 |
| `E-C` | 删尾句 | 每节末句若为「综上所述／由此可见／总体而言」，删 |

三条都是**删**，不是改。改出来的句子仍然是原来的结构，删掉之后剩下的才是论证。

## banned_patterns

正文出现任一即判 `FAIL`。附录不受限。

| 类别 | 模式 | 例 |
|---|---|---|
| 流程编号 | `FLOW #\d+`、`§\d+\.\d+（FLOW`、`Step \d` | "资产清单与权属（FLOW #8）" |
| 状态码 | `CONFIRMED`、`PARTIALLY_SUPPORTED`、`INDETERMINATE`、`NOT_COMPARABLE`、`SOURCE_UNAVAILABLE`、`DATA_QUALITY_WARNING`、`UNDEFINED_THRESHOLD` | "估值判断 `PARTIALLY_SUPPORTED`" |
| 测试语 | `PASS`、`FAIL`、`断言`、`自检通过` | "三类型数字是否混列 PASS" |
| 内部标尺 | `bands \d+/\d+`、`阈值档位`、`低位（bands` | "中位（bands 95/90）" |
| 修订语 | `初稿`、`本版`、`上一版`、`修订说明`、`更正清单` | "初稿把 DT51 当作……" |
| 运行语 | `run_log`、`执行 skill`、`按 FLOW 执行`、`产出物` | "执行 skill v1.0.0" |
| 自指语 | `本报告`、`本文`、`本篇`、`本报告组` 作论证主语 | "本报告不预设扩样后结论不变" |
| 读者语 | `读者可以`、`可以看到`、`请注意`、`需要说明的是`、`值得注意的是`、`综上` | "读者可以不同意，但能看见怎么选的" |

自指语与读者语按出现次数判（正文 0 次）；其余元话语不以固定词频判失败。必要的方法说明与证据边界应保留，但按 `V-6` 降级到括号、图注或附录。

## figure_table_policy

| 项 | 规则 |
|---|---|
| 编号 | `表 1`／`图 1`，全文连续，不按章重排 |
| 标题位置 | 表题与图题均在对应图表上方，资料来源在下方，口径说明第三行；全篇统一，不得一半在上、一半在下 |
| 表格顺序 | 论证段 → 表题 → 表格 → 资料来源 → 口径说明，顺序不可颠倒 |
| **空间归属** | **图必须内嵌在报告正文里**，用 `![图 N 标题](figures/figN_xxx.png)`（投后链路为 `charts/`）就地嵌入，紧跟其论证段落；不得把图当作报告之外的附件 |
| **禁止指路** | 不得写「图 1 见 charts/fig1.svg」「文件：charts/xxx」「另有图件见某目录」——读者不应被要求打开第二个文件才能看图 |
| 单次出现 | 同一张图在正文只出现一次；附录汇总表只列图号与标题，不重复贴图 |
| 阅读版 | 交付时同时给 `.html` 单文件版，图以 base64 内嵌，拷走即完整；`.md` 用相对路径引用，`.html` 用内嵌 |
| 资料来源 | 每张必写，格式 `资料来源：{披露文件}、{数据库}、整理（自算）` |
| 口径说明 | 每张必写第三行，给出**与披露值的差额及原因**（基准日差异／四舍五入／样本覆盖）。只写"数据来源：某年报"不构成口径说明。自算图表若无对应披露值可比，写"无直接可比披露值"并说明分母取值。写法见 SKILL.md《成稿范式》的「图：四行式」与「自算值与披露值不一致」 |
| 宽表配置 | 首列名称列左对齐、数值列右对齐；差额列用 `+` / `−` 显式带符号；缺失值写 `未披露`（不留空、不写 `N/A`、不写 `—`）；合计行标 `合计 / 加权` 且能与披露值并列比较 |
| 自算图表 | 资料源须写"整理（自算）"，不得伪装成披露数据；**不写"本报告整理"**——它与 `V-1` 自指语 0 次冲突，自算属性由"（自算）"承担 |
| 数据表上限 | 无固定行数；按可读性拆分，核心测算不得因行数移出正文 |
| 禁止 | 只罗列字段的"机械表"（如把招募书的产品要素表原样搬入正文）——这类表移附录 |

## visual_style（阅读版 `.html`）

版面不靠手写 CSS 复现，由 `tools/render_report.py` 统一产出。脚本只做四件事：markdown 块级解析（标题／表格／图／有序与无序列表／引用块／代码块／分隔线）、行内解析（图／链接／加粗／斜体／行内码）、按 md 所在目录解析图片并转 base64 内嵌、套上固定 CSS。零第三方依赖。

```bash
python tools/render_report.py report_XXXXXX.md                       # 输出同名 .html
python tools/render_report.py report.md -o out/r.html --title "…"    # 指定路径与标签标题
```

| 项 | 值 |
|---|---|
| 主色 `--ink` | `#1F3864` 深蓝：h1/h2/h3、表头底色、封面表左列 |
| 强调色 `--acc` | `#C55A11` 橙：h2 左侧 5px 竖线、链接 |
| 分隔线 `--line` | `#DCE3F0` 浅蓝灰 |
| 页面 | 底色 `#F4F6FA`；白纸卡片 `max-width:960px`、`padding:56px 64px 72px`、阴影 `0 2px 18px rgba(31,56,100,.08)` |
| 字体 | `"Microsoft YaHei","微软雅黑",-apple-system,sans-serif`；正文 15.5px／行高 1.85 |
| 标题 | h1 25px 带 3px 深蓝底边；h2 20px 带 5px 橙色左边线；h3 17px |
| 表 | 13.5px；表头深蓝反白；单元格 `#DCE3F0` 细边；偶数行 `#F7F9FD` 斑马纹 |
| 图 | 满宽、`1px` 浅边、4px 圆角 |
| 代码块 | `#F7F9FD` 底、左侧 3px 橙线、12.5px 等宽字体，围栏内不解析行内语法 |
| 封面表 | 文档内**第一个** table 视为封面信息表：首列固定 118px、加粗深蓝、不换行 |
| 打印 | `@media print` 去页面底色、卡片阴影与内边距 |

三条复现纪律：

- `.md` 与 `.html` **同源同序**：改完 md 重新渲染，不手改 html。
- 图片走相对路径（`figures/figN_xxx.png` 或投后链路的 `charts/figN_xxx.png`），脚本按 md 所在目录解析后内嵌；**md 里绝不写绝对路径**。
- 内嵌后单文件体积约等于「正文 + 图总和」，五百到八百 KB 属正常；超过 2 MB 说明图未压缩，回上游处理。

改配色只动脚本的 `CSS` 常量，不改解析逻辑；改动后重跑一份既有报告，确认元素级结构未变（h1/h2/p/table/figure/img 计数一致）。

## review_checklist

在既有结构及数字核验步骤中使用以下清单，发现问题直接修正报告；不要求固定轮次或独立 review 文件。

### 内容与逻辑

| id | 检查项 | 不通过示例 |
|---|---|---|
| `C-1` | 重要结论有相称的事实、数字或条款支撑 | "资产质量优秀"无证据 |
| `C-2` | 重要判断考虑不利证据或替代解释，无法取得时说明限制 | 只写优点 |
| `C-3` | 收入 → EBITDA → 可供分配的传导有量化 | "成本控制良好"无数 |
| `C-4` | 估值参数被独立评价，不是照抄 | "折现率 5%，合理" |
| `C-5` | 分派率与 IRR 分开表述，且给出计算过程 | 只给结果 2.67% |
| `C-6` | 情景含悲观，且悲观情景有触发路径 | 只做中性 |
| `C-7` | 缺失资料如实标注并说明证据等级下降 | 假装已核验 |
| `C-8` | 假设与披露不混 | 把 3.5% capex 写成"披露的 capex" |

### 结构与表达

| id | 检查项 | 不通过示例 |
|---|---|---|
| `E-1` | 全文无 `banned_patterns` 命中 | 出现 `FLOW #8` |
| `E-2` | 标题准确反映章节内容，重要章节可体现判断 | 标题与正文不符 |
| `E-3` | 摘要能独立成立（不读后文也能懂结论） | 摘要依赖后文才能理解 |
| `E-4` | 无无意义的跨章重复 | 同一论证机械重复 |
| `E-5` | 必要图表有资料来源，核心测算清楚 | 图表无法解释或无来源 |
| `E-6` | 段落长度和表格布局便于阅读 | 长段或表格影响理解 |

## self_check

`report_metrics.json` 必含字段，供 `tests/` 读取：

## versioning_rule

- 报告版本号与 skill 版本号分开记：报告 `v1.0` 起，skill `1.0.0` 起。
- 报告每轮实质修订升 `v0.x`，交付版升 `v1.0`；**版本变更记录只在附录**。
- 文风规则（`voice_rules`）新增或收紧时在附录记一条，说明触发它的反例；可机检项（自指语、读者语、`we` 频次）入 `report_metrics.json`。
- skill 的文风规则变更应同步说明依据和适用边界；`template/report_style_analysis.md` 保留历史统计，不能覆盖当前规则，也不要求每项通用写作规则都由历史样本配额推出。

--{abstract}--
将研究结果组织成通用于不同公募 REITs 的报告：结论有证据，参数有依据，测算可复核，判断带档位。章节按读者的问题组织，不复制执行工序；不得套用历史案例结论。用记者腔写——主语是人与钱，不是"本报告"；每个数字带参照系。投前中文正文不少于 15,000 字符，投后不少于 3,000 字符，横向基准按内容需要不设下限；专题按任务约定，均不设上限。计数不含封面与附录，篇幅用于解释而非重复。
--{/abstract}--

# Step 0：输入与论点

#1 --{动作}-- [非数据]
**核验上游研究结果，连判断档位一起核**
- 检查事实、模型、假设、结论证据和来源索引；可沿用等价底稿，不为文件形式重复造表。
- 横向基准报告另核 `findings.csv`：每行是否带 `finding_id / evidence_state / 锚点 / 限定 / 章节映射 / 依赖 / 失效条件`。缺核心字段的判断不得作为确定结论；先回上游补证或明确降级。
- 建立逐条映射表 `finding_id → 主章节 / 复用章节 / 使用状态`，并登记章节核心判断反向对应的 finding。摘要、表格、图注复用同一判断时，保留一致的证据状态和限定；不得把多条低档 finding 拼接成高档结论。
- 检查 `depends_on`：分母、时点、资产边界等关键依赖未核实，阻断其下游排名、定价或因果结论；仍可写不依赖该缺口的结论，并限定影响范围。
- 区分排名样本、模式参照与背景参照；参照标的不得进入排名、位置表或排名结论。象限及类别标签只从锁定数据表/脚本读取，跨章节冲突须回上游修正后整体更新。
- 区分历史事实、文件预测、独立假设与派生值，关键数字可定位原文或模型。
- 非核心资料缺失时明确限制并继续可支持的写作；核心缺口退回补证，无法补齐时限定受影响结论并标为部分完成，不机械阻断全部写作。影响判断的缺口及证据边界须在正文说明，不用文字掩盖缺失。
[输出]：可写范围与缺口

#2 --{动作}-- [非数据]
**确定主论点与依据**
- 说明资产是什么、价值是否成立及其原因；支撑论点数量按证据确定。
- 检查重要判断的不利证据和失效条件，不强造反证。
[输出]：主论点及支撑依据

#3 --{动作}-- [非数据]
**组织章节与读者的问题**
- 按 `outline_schema` 选骨架：投前用 `pre`、投后用 `post`、横向基准用 `comparison`。三套骨架的问题清单不同，不得混用——横向基准套 `pre` 会写出"值不值得买"，那不在它的能力范围内。`comparison` 的摘要只回答“在同类里排在哪里、名次稳不稳、差异由什么造成”，不套用投前的估值与买入判断。
- 每章回答一个问题，问题写成疑问句；答不出就删章或并章。
- 必要的背景和法律说明保留，但不因"每章都要有判断"而强造因果。
[输出]：报告提纲（章 → 疑问句）

#4 --{动作}-- [非数据]
**确定清晰标题**
- 标题准确反映内容；证据充分时用判断式标题，法律、结构和计算说明可用描述式标题。
- 不强制标题格式、长度或论断比例，不把相关变化写成未经证明的因果。
- 投后七章按 `S-11` 的 `职能短语：本期判断` 命名（三元并列／双主体对撞／反转／转折，见 SKILL.md《成稿范式》）。自检：把标题里的本期事实换成上一期，句子还成立就是背景，重写。写不出"冒号后的判断"，说明这一章没结论，回去补论证。
[输出]：章节标题

#5 --{动作}-- [非数据]
**撰写自足摘要**
- `comparison` 骨架只概括样本位置、名次是否稳定、差异由什么结构造成，以及下一期什么数据会改写结论；不要写“值不值得买”、目标价或评级。
- `pre` / `post` 报告再概括投资对象、现金流来源、主要分歧、估值和价格条件、回报边界及关键风险。
- 说明结论及前提；无需固定占比或逐问限句，不依赖后文章节引用。
[输出]：投资摘要

# Step 1：正文与证据

#6 --{动作}-- [非数据]
**展开分析与计算**
- 按结论、证据、机制和投资含义展开，篇幅服从问题；法律判断可由条款支撑，不要求每节凑数字或反证。
- 现金流及估值章节在正文展示关键公式、参数、参数合理性、逐项计算及结果，并解释披露复算与独立测算差异。
- 风险收益比较在同一情景下展示现金分派、价值变化、可测总回报和风险触发条件；证据不足说明影响。
[输出]：完整正文

#7 --{动作}-- [数据]
**标明数字类型与口径**
- 历史事实、文件预测、独立假设可同表比较，但须分列或逐行标明类型、期间、单位、来源和分母。
- 区分资产/基金价值、可供分配/实际分派、分派率/总回报；不得在写作时新造数字，需新增测算则返回模型。
- 自算值与披露值不一致时，按 `S-13` 的四步交代：给自算值、给披露值、量化差额、把差额归到具体口径（基准日差异、四舍五入、样本覆盖）。禁止"基本一致"、禁止改成披露值、禁止两个都写却不解释。
[输出]：可追溯的数据展示

#8 --{动作}-- [非数据]
**配置必要图表**
- 按表达需要使用结构图、租约到期图、现金流桥接和情景表；不设数量配额或固定行数上限。
- 图表连续编号，标注来源、期间及自算属性；核心测算不因表长而全部移附录。
- 执行 `figure_delivery_policy`：将采用的图片与图表嵌入对应正文，不得只列图片链接；维护图号、素材路径、finding、章节、图注与来源的内部清单。Markdown 用相对图片引用并随报告打包资源；HTML 内联 SVG 或 data URI，Word/PDF 实际嵌入图片。
- 上游取数流程已指定图件的（如投后 #22 指定"出租率与租金双轴图""收入与可供分配柱线图"），这些是**必配项**；在必配项之外自加的图，须在图注第一句写明它替代表格的哪一栏、论证什么，否则删掉——图的成本是版面，收益必须可指认。
- **图写在正文里，不写在附件里**：用 `![图 N 标题](figures/figN_xxx.png)`（投后链路为 `charts/`）就地嵌入，紧跟它所支撑的段落；图题在上、资料来源在下、口径说明第三行。
- **口径说明必须写差额**（见 SKILL.md《成稿范式》「图：四行式」与 `figure_table_policy`）：第三行不能停在"数据来源"，要给出这张图与披露值的差多少、为什么差。写不出差额的图，说明它只是在复述披露，不构成论证。
- **不得指路**：禁止「图 1 见 charts/xxx」「图件另存于某目录」这类写法。判断标准：把报告单独拷走，读者是否还能看到图；看不到就是没嵌进去。
- 交付时同步生成 `.html` 单文件版（图 base64 内嵌），`.md` 与 `.html` 同源同序，不得一版有图一版无图。命令：`python tools/render_report.py report.md`（默认输出同名 `.html`；`-o` 指定路径，`--title` 覆盖标签标题）。脚本从 md 所在目录解析图片相对路径，零第三方依赖，输出后打印内嵌图数与表格数，缺图会列出路径而不是静默跳过。
[输出]：正文图表

#9 --{动作}-- [非数据]
**清理语言与过程记录**
- 正文用自然语言说明证据限制，删除流程编号、状态码、修订经过及空泛套话。
- 删除自指与读者语：`本报告`、`本文`、`本篇`、`读者可以`、`需要说明的是`、`值得注意的是`、`综上`。判据不是词频，是这句在说"我"还是在说"它"。
- 来源标注可保留必要的"本报告测算"，但每出现一次就问：换成"按 2025 年报重算"是否更具体。可以换的一律换。
[输出]：清晰可读的正文

#10 --{动作}-- [非数据]
**记者腔改写：把"本报告如何处理"改成"谁因为什么多赚少赚"**
- 逐段问一句：念给没看过材料的人听，他能不能说出"谁受损、谁受益、大概多少"。说不出的是方法论述，移附录或删。
- 六种必改：**自指**（"本报告回答三件事"→直接给三句判断）；**邀读者核对**（"读者可以不同意"→直接陈述选样事实）；**判决交给本报告**（"本报告倾向"→"我们倾向"）；**形容词结论**（"质量相对较弱"→位次＋幅度＋与第一名差）；**裸数字**（"减值 7,152 万"→"相当于全年可供分配的 41%"）；**清单体**（整节"第一第二第三"→一段一个因果）。
- 三条机械动作：**换标测试**（把标的换成另一只仍成立＝没有信息量，删）；**删首段**（交代背景、定义概念、复述前文的，整段删）；**删尾句**（"综上所述""由此可见"一律删）。
- 必要的口径说明不算废话，但要降到括号、图注或附录，正文最多留一句"（口径见附录）"。判据：删掉它结论是否仍成立。
- 全篇"我们"只用于三件事：给倾向、承认不知道、承担测算。每千字不超过一次；超出说明在替读者下结论，停下重写。
- 跑一遍 `python tools/check_voice.py <report.md>`：自指语与读者语应清零，裸数字逐条补参照系。工具只报位置不判风格，命中后人工决定删或补。
[输出]：记者腔改写后的正文

# Step 2：复核与交付

#11 --{动作}-- [数据]
**检查结构和重复**
- 检查必需主题有无遗漏、摘要能否独立理解、论证及术语是否清楚，删去重复、跳跃推理和无关背景；直接修正正文，不另建检查记录。
- 字数建议仅用于分配篇幅，不按标题样式、段长或章节配额机械判失败。
- 投后报告过《成稿范式》的六问：资料完整性是否写明哪几份文件不能用；章节标题换掉本期事实后是否不再成立；每段首句能否单独当结论；每张图表的口径说明是否写了差额；自算与披露不一致处是否用了四步交代法；摘要是否拆掉了一个"看起来好、实际不可持续"的指标。任一为否，回改对应章节，不记入检查清单。
- 摘要自查一条：第 4 段必须存在且真的在拆一个指标（高分派率／收缴率破百／出租率反弹）。没有这一段，摘要等于复述季报。
[输出]：结构与表达修正后的正文

#12 --{动作}-- [数据]
**核验正文长度**
- 运行 `python tools/count_report_words.py <report.md>`，分别记录中文正文、英文字母、数字字符和总字符数。
- 投前中文正文至少 15,000 字符，投后至少 3,000 字符，均不设上限；专题按任务约定。不足时补证据、机制与测算，不靠附录或重复扩充。
- 详细指标保留在 `report_metrics.json`，首页只需说明正文长度与口径。
[输出]：字数指标

#13 --{动作}-- [数据]
**核对数字与结论**
- 正文关键数字与权威模型及底稿对账；冲突时查明来源并修正，不盲从旧底稿。
- 横向基准逐条执行双向审计：每个 finding 的所有正文复用点逐一核对数字、方向、证据状态和限定；每个核心判断反查有效 finding、来源锚点和已满足的依赖。不得以“已出现若干 finding / 已有章节索引”代替核对。
- 对所有分类标签（含象限、组内唯一、领先/落后、纳入/排除）校验同源表一致性，检查唯一性前提和样本变动影响；有冲突时回上游修正并同步重算表图和正文。
- 从正文参数与公式复算关键结果；披露值、复算值、独立值及不同现金流层级分别核验。
- 核查来源、参数合理性、估值层级与风险传导是否支持结论；预测 IRR/XIRR 可使用明示的期限和日期假设，资料不足时限定结论。
[输出]：完成必要核验并修正的报告

#14 --{动作}-- [数据]
**交付与归档**
- 交付报告和字数指标；附录保留必要来源、公式及假设。影响判断的未解决问题须在相关正文说明，核心问题未解决时标注部分完成。
- 图片素材目录是报告内部依赖，不作为默认独立交付物；交付前确认采用图表均嵌入正文且路径/渲染有效。只有用户明确要求图片素材时才另行呈现。
- 不要求固定审稿轮次，不生成独立 review 文件；必要核验在 #11–#13 完成，历史版本交给 Git 保存。
[输出]：报告与字数指标
