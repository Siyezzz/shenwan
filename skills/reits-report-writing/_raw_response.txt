# 公募 REITs 研究报告写作

本 skill 是一个 flow（可执行写作流程），**处在取数层的下游**。

**它解决的是一个问题**：上游研究 FLOW 跑完之后，手上有一堆正确的数字、一个可重算的模型、一张假设表，但写出来的东西读起来像运行日志。原因是**取数流程的骨架（Step 0 → 分层 → 归因 → 测算 → 估值 → 结论）与投研报告的骨架（投资问题 → 论证 → 判断）不是同一个东西**。把 FLOW 的步骤名当章节名，就等于把工序单交给了客户。

**执行方式**：阅读同目录下的 FLOW.md，按 `#1 → #15` 顺序执行。`#1` 做输入准入，`#2` 定论点树，`#3`–`#4` 定骨架与标题，`#5`–`#8` 写内容，`#9`–`#12` 清洗与核验，`#13`–`#14` 两轮审稿，`#15` 交付。

**运行前检查**：
1. 上游 FLOW 的产物必须齐备：事实底稿、模型、假设登记、claim 裁决表、来源索引。缺任何一项，先回上游补齐，不要用"文字补"掩盖"数据缺"。
2. 报告里的每一个数字必须能在上游产物里找到，**不允许在写作阶段新造数字**。需要新数字时，退回上游算，不许在正文里"估一个"。
3. 结论先于文字。`#2` 的论点树没定下来之前，不写任何一段正文。

**输出位置**：上游约定的 `outputs/{case}/`，文件名沿用既有命名（`report_{code}.md`）。同时产出 `report_metrics.json`（字数、图表数、禁用词命中数），供自动化测试读取。

## 这个 skill 回答什么

**不是"怎么把话说完整"，是"怎么让一个没读过原始材料的人，在 15 分钟内做出买或不买的判断"。**

所以必须做到三件事，缺一不算完成：

1. **结论在前，且是判断不是描述。** 第一章读完必须知道：这是什么、赚什么钱、值不值、什么情况下不值。
2. **每一节回答一个投资问题。** 节标题是论断，不是话题。"行业现状""运营情况"不是论断；"出租率修复靠降价换来，且降价尚未结束"是论断。
3. **过程与结论分离。** 自检、口径裁决、纠错、数据缺口属于附录。正文只留论证。

## 三条硬约束

- **正文不出现流程编号与状态码。** `FLOW #n`、`run_log`、`PASS/FAIL`、`CONFIRMED`、`bands 95/90` 一律不得进入正文，只能出现在附录的执行记录或 claim 表里。
- **不写"我做了什么"，只写"事实是什么、意味着什么"。** "本报告的处理是双列并行" → "两个口径都保留：判断收现能力用四季加总，判断全年现金生成用年报数"。
- **不注水。** 字数不够时补的是**论证**（机制、反证、敏感性、可比对照），不是形容词与重复。判据：新增的每一段，删掉之后结论会变弱——如果删掉结论不变，那段是水。

## 与上游 FLOW 的接口

| 上游产出 | 本 skill 的用法 | 不得做的事 |
|---|---|---|
| `source_index.csv` + 页码锚点 | 正文数字的原始证据入口；`assumptions.csv` 区分研究假设 | 不把来源索引误当事实表，不在正文里新造数字 |
| `models/cash_flow_model.xlsx` | 情景与敏感性的数来自这里 | 不在正文里手改模型结果 |
| `assumptions.csv` | 每条假设进附录登记表；正文引用时标注"假设" | 不把假设写成"披露" |
| `claims_verdict.csv` | 裁决结果进正文的结论句，`claim_id` 与状态码进附录 | 不在正文里展示 `claim_id` |
| `source_index.csv` | 附录的来源索引；正文用"文件 + 页码"锚点 | 不用"据披露"这类无锚点表述 |

## 学谁的行文

本 skill 的文风规则来自对 11 份卖方行业深度报告（`_ref/202608研报/`，408 页、327 张图表）的结构统计，主要可迁移的四条：

1. **首页"投资要点"4–6 条，每条一个完整论证**：`结论句。论据（数字＋同比＋时间）。含义。` 最后一条固定是投资意见，倒数第一条固定是风险提示。
2. **二级标题 41% 带冒号或破折号，后半句是判断**：「底部特征：钢企利润情况基本处于历史底部」「景气回落的原因——地产需求疲弱，但边际影响预期弱化」。
3. **图表密度约每 1.25 页一张**，每张图下方必须写 `资料来源：A、B、本报告整理`。
4. **"我们认为"是稀缺词**，11 份报告平均只用 1.3 次，且几乎都出现在与市场共识相反的判断处。滥用会稀释它。

统计口径与原始记录见 `template/report_style_analysis.md`。

## report_input_contract

上游必须交付的 5 类产物。缺一项则 `#1` 判定 `BLOCKED`，不得进入写作。

| id | 产物 | 必备内容 | 缺失后果 |
|---|---|---|---|
| `IN-1` | 事实底稿 | 每个数字带 `文件 + 页码` 锚点；分 `历史事实 / 文件预测 / 独立假设` 三类 | 正文无法写锚点，全部结论降级 |
| `IN-2` | 现金流模型 | 参数与公式分离；可改参数重算；含三情景 | 第六章无法写，第八章 IRR 不可复核 |
| `IN-3` | 假设登记表 | 每条含 `取值 / 依据 / 来源 / 敏感性 / 状态` | 正文无法区分假设与事实 |
| `IN-4` | claim 裁决表 | 每条含 `aggregation / threshold / observed / verdict / evidence_ref` | 结论句无出处 |
| `IN-5` | 来源索引 | 每条含 `文件名 / 类型 / 日期 / 页数 / URL / 本地路径 / 状态` | 附录无法生成，读者无法回查 |

## section_contract

每节写作时逐条自检。**`question` 一栏是这一节的唯一目的**，写不出来就说明这节该删或该并。

| 字段 | 必填 | 说明 |
|---|---|---|
| `section_id` | 是 | 与 `outline_schema` 对应 |
| `question` | 是 | 一句话，必须是疑问句 |
| `claim` | 是 | 本节要证明的判断，一句话 |
| `evidence` | 是 | 支撑该判断的数字，至少 3 个，每个带锚点 |
| `counter` | 是 | 反面证据或不利解释，至少 1 条。**写不出反面证据的节不得判 `CONFIRMED`** |
| `implication` | 是 | 对投资判断的含义，一句话 |
| `min_words` | 是 | 见 `outline_schema` |
| `figures` | 否 | 本节需要的图表编号 |

## style_rules

| id | 规则 | 判据（可机检） |
|---|---|---|
| `S-1` | 结论先行：每节第一段第一句必须是判断句，不是背景句 | 首段首句不含"随着""近年来""作为"开头 |
| `S-2` | 论断式标题：二级标题须含判断（动词/形容词/比较/因果），不得为纯名词短语 | 标题含 `：`、`——`、`，` 之一，或含判断词 |
| `S-3` | 一段一义：单段 80–250 字，不超过 300 字 | 段落中文字符数 |
| `S-4` | 数字必带三件套：口径、期间、来源锚点 | 关键数字后 20 字内出现 `（口径，期间，文件 pXX）` |
| `S-5` | 三类数字分列：历史事实／文件预测／独立假设，不得同列 | 表格表头或行标注类型 |
| `S-6` | 图表密度 ≥ 每 2,000 字 1 张，且每张有 `资料来源` | 计数 |
| `S-7` | 分级表达：`已证实 / 证据不足 / 无法判断 / 不可比 / 不可得`，不用状态码 | 正文不出现 `CONFIRMED` 等 |
| `S-8` | 克制"我们认为"：全文 ≤3 次，且只用于与共识相反的判断 | 计数 |
| `S-9` | 不写过程：不出现"本报告的处理是""初稿写…本版改为""经核对后……" | 禁用词表 |
| `S-10` | 风险必带传导链：机制 → 证据 → 触发条件 → 财务影响 → 监测指标 | 五要素齐全 |

## banned_patterns

正文出现任一即判 `FAIL`。附录不受限。

| 类别 | 模式 | 例 |
|---|---|---|
| 流程编号 | `FLOW #\d+`、`§\d+\.\d+（FLOW`、`Step \d` | "资产清单与权属（FLOW #8）" |
| 状态码 | `CONFIRMED`、`PARTIALLY_SUPPORTED`、`INDETERMINATE`、`NOT_COMPARABLE`、`SOURCE_UNAVAILABLE`、`DATA_QUALITY_WARNING`、`UNDEFINED_THRESHOLD` | "估值判断 `PARTIALLY_SUPPORTED`" |
| 测试语 | `PASS`、`FAIL`、`断言`、`自检通过` | "三类型数字是否混列 PASS" |
| 内部标尺 | `bands \d+/\d+`、`阈值档位`、`低位（bands` | "中位（bands 95/90）" |
| 修订语 | `初稿`、`本版`、`上一版`、`修订说明`、`更正清单` | "初稿把 DT51 当作……" |
| 运行语 | `run_log`、`执行 skill`、`按 FLOW 执行`、`产出物` | "执行 skill v1.0.0" |
| 元话语 | `本报告的处理是`、`需要说明的是`、`必须指出`（连用 ≥3 次/节） | — |

## figure_table_policy

| 项 | 规则 |
|---|---|
| 编号 | `表 1`／`图 1`，全文连续，不按章重排 |
| 标题位置 | 表在上、图在下；标题在图表**上方** |
| 资料来源 | 每张必写，格式 `资料来源：{披露文件}、{数据库}、本报告整理` |
| 自算图表 | 资料源须写"本报告整理"，不得伪装成披露数据 |
| 数据表上限 | 正文数据表单表不超过 12 行；超出拆表或移附录 |
| 禁止 | 只罗列字段的"机械表"（如把招募书的产品要素表原样搬入正文）——这类表移附录 |

## word_count_policy

| 项 | 定义 |
|---|---|
| 计数对象 | 中文字符（`[\u4e00-\u9fff]`） |
| 计入 | 正文第 1–10 章（投前）／第 1–7 章（投后），含正文内表格中的分析性文字 |
| 不计入 | 封面、目录、附录、参考文献、来源索引、运行日志、自检表、版本变更记录 |
| 分别报告 | 中文正文字符数／英文字母数／数字字符数／Markdown 总字符数，四项分开，不得合并称"字数" |
| 投前下限 | **≥15,000** 中文正文；目标 17,000–20,000 |
| 投后下限 | ≥3,000 中文正文（不设上限） |
| 反注水 | 连续 30 字以上与另一段完全重复即判重复；同一表格出现两次即判重复 |
| 工具 | `python tools/count_report_words.py <report.md>` |

## review_checklist

### 第一轮：内容与逻辑（`R1`）

| id | 检查项 | 不通过示例 |
|---|---|---|
| `R1-1` | 每条结论都能在正文找到至少 3 个支撑数字 | "资产质量优秀"无数字 |
| `R1-2` | 每条重要结论都有反面证据或不利解释 | 只写优点 |
| `R1-3` | 收入 → EBITDA → 可供分配的传导有量化 | "成本控制良好"无数 |
| `R1-4` | 估值参数被独立评价，不是照抄 | "折现率 5%，合理" |
| `R1-5` | 分派率与 IRR 分开表述，且给出计算过程 | 只给结果 2.67% |
| `R1-6` | 情景含悲观，且悲观情景有触发路径 | 只做中性 |
| `R1-7` | 缺失资料如实标注并说明证据等级下降 | 假装已核验 |
| `R1-8` | 假设与披露不混 | 把 3.5% capex 写成"披露的 capex" |

### 第二轮：结构与表达（`R2`）

| id | 检查项 | 不通过示例 |
|---|---|---|
| `R2-1` | 全文无 `banned_patterns` 命中 | 出现 `FLOW #8` |
| `R2-2` | 每节标题是论断 | "运营情况" |
| `R2-3` | 摘要能独立成立（不读后文也能懂结论） | 摘要里出现"见 §8.2" |
| `R2-4` | 无跨章重复（同一论证出现 ≥2 次） | §5 与 §8 各讲一遍以价换量 |
| `R2-5` | 图表密度达标，且每张有资料来源 | 5,000 字 0 图 |
| `R2-6` | 段落长度合规（80–300 字） | 出现 600 字长段 |
| `R2-7` | 正文中文 ≥ 下限，且无 30 字重复 | 靠附录堆字数 |
| `R2-8` | 术语一致（同一指标全文一个叫法） | "有效租金"与"实收租金"混用 |

## quality_states

沿用上游七态，但**只允许出现在附录**。正文使用对应的自然语言：

| 状态码 | 正文表述 |
|---|---|
| `CONFIRMED` | 已证实／可以确认 |
| `PARTIALLY_SUPPORTED` | 方向可确认，细节证据不足 |
| `INDETERMINATE` | 现有材料无法判断 |
| `NOT_COMPARABLE` | 口径不同，不可直接比较 |
| `SOURCE_UNAVAILABLE` | 该材料未公开披露 |
| `DATA_QUALITY_WARNING` | 披露口径存在问题 |
| `UNDEFINED_THRESHOLD` | 缺少可参照的阈值 |

# 公募 REITs 研究报告写作

本 skill 是一个 flow（可执行写作流程），**处在取数层的下游**。

**它解决的是一个问题**：三个业务 FLOW 跑完之后，手上有一堆正确的数字、一个可重算的模型、一张假设表，但写出来的东西读起来像运行日志。原因是**取数流程的骨架（Step 0 → 分层 → 归因 → 测算 → 估值 → 结论）与投研报告的骨架（投资问题 → 论证 → 判断）不是同一个东西**。把 FLOW 的步骤名当章节名，就等于把工序单交给了客户。

**执行方式**：阅读同目录下的 FLOW.md，按 `#1 → #15` 顺序执行。`#1` 做输入准入，`#2` 定论点树，`#3`–`#4` 定骨架与标题，`#5`–`#8` 写内容，`#9`–`#12` 清洗与核验，`#13`–`#14` 两轮审稿，`#15` 交付。

**运行前检查**：
1. 上游 FLOW 的产物必须齐备：事实底稿、模型、假设登记、claim 裁决表、来源索引。缺任何一项，先回上游补齐，不要用"文字补"掩盖"数据缺"。
2. 报告里的每一个数字必须能在上游产物里找到，**不允许在写作阶段新造数字**。需要新数字时，退回上游算，不许在正文里"估一个"。
3. 结论先于文字。`#2` 的论点树没定下来之前，不写任何一段正文。

**输出位置**：上游约定的 `outputs/{case}/`，文件名沿用既有命名（`report_{code}.md`）。同时产出 `report_metrics.json`（字数、图表数、禁用词命中数），供自动化测试读取。

## 这个 skill 回答什么

**不是"怎么把话说完整"，是"怎么让一个没读过原始材料的人，在 15 分钟内做出买或不买的判断"。**

所以必须做到三件事，缺一不算完成：

1. **结论在前，且是判断不是描述。** 第一章读完必须知道：这是什么、赚什么钱、值不值、什么情况下不值。
2. **每一节回答一个投资问题。** 节标题是论断，不是话题。"行业现状""运营情况"不是论断；"出租率修复靠降价换来，且降价尚未结束"是论断。
3. **过程与结论分离。** 自检、口径裁决、纠错、数据缺口属于附录。正文只留论证。

## 三条硬约束

- **正文不出现流程编号与状态码。** `FLOW #n`、`run_log`、`PASS/FAIL`、`CONFIRMED`、`bands 95/90` 一律不得进入正文，只能出现在附录的执行记录或 claim 表里。
- **不写"我做了什么"，只写"事实是什么、意味着什么"。** "本报告的处理是双列并行" → "两个口径都保留：判断收现能力用四季加总，判断全年现金生成用年报数"。
- **不注水。** 字数不够时补的是**论证**（机制、反证、敏感性、可比对照），不是形容词与重复。判据：新增的每一段，删掉之后结论会变弱——如果删掉结论不变，那段是水。

## 与上游 FLOW 的接口

| 上游产出 | 本 skill 的用法 | 不得做的事 |
|---|---|---|
| `facts.yaml` / 数据矩阵 | 正文所有数字的唯一来源 | 不在正文里重算上游已算过的数 |
| `model/cashflow.xlsx` | 情景与敏感性的数来自这里 | 不在正文里手改模型结果 |
| `assumptions.csv` | 每条假设进附录登记表；正文引用时标注"假设" | 不把假设写成"披露" |
| `claims_verdict.csv` | 裁决结果进正文的结论句，`claim_id` 与状态码进附录 | 不在正文里展示 `claim_id` |
| `source_index.csv` | 附录的来源索引；正文用"文件 + 页码"锚点 | 不用"据披露"这类无锚点表述 |

## 学谁的行文

本 skill 的文风规则来自对 11 份卖方行业深度报告（`_ref/202608研报/`，408 页、327 张图表）的结构统计，主要可迁移的四条：

1. **首页"投资要点"4–6 条，每条一个完整论证**：`结论句。论据（数字＋同比＋时间）。含义。` 最后一条固定是投资意见，倒数第一条固定是风险提示。
2. **二级标题 41% 带冒号或破折号，后半句是判断**：「底部特征：钢企利润情况基本处于历史底部」「景气回落的原因——地产需求疲弱，但边际影响预期弱化」。
3. **图表密度约每 1.25 页一张**，每张图下方必须写 `资料来源：A、B、本报告整理`。
4. **"我们认为"是稀缺词**，11 份报告平均只用 1.3 次，且几乎都出现在与市场共识相反的判断处。滥用会稀释它。

统计口径与原始记录见 `template/report_style_analysis.md`。

## report_input_contract

上游必须交付的 5 类产物。缺一项则 `#1` 判定 `BLOCKED`，不得进入写作。

| id | 产物 | 必备内容 | 缺失后果 |
|---|---|---|---|
| `IN-1` | 事实底稿 | 每个数字带 `文件 + 页码` 锚点；分 `历史事实 / 文件预测 / 独立假设` 三类 | 正文无法写锚点，全部结论降级 |
| `IN-2` | 现金流模型 | 参数与公式分离；可改参数重算；含三情景 | 第六章无法写，第八章 IRR 不可复核 |

## section_contract

每节写作时逐条自检。**`question` 一栏是这一节的唯一目的**，写不出来就说明这节该删或该并。

| 字段 | 必填 | 说明 |
|---|---|---|
| `section_id` | 是 | 与 `outline_schema` 对应 |
| `question` | 是 | 一句话，必须是疑问句 |
| `claim` | 是 | 本节要证明的判断，一句话 |
| `evidence` | 是 | 支撑该判断的数字，至少 3 个，每个带锚点 |
| `counter` | 是 | 反面证据或不利解释，至少 1 条。**写不出反面证据的节不得判 `CONFIRMED`** |
| `implication` | 是 | 对投资判断的含义，一句话 |
| `min_words` | 是 | 见 `outline_schema` |
| `figures` | 否 | 本节需要的图表编号 |

## style_rules

| id | 规则 | 判据（可机检） |
|---|---|---|
| `S-1` | 结论先行：每节第一段第一句必须是判断句，不是背景句 | 首段首句不含"随着""近年来""作为"开头 |
| `S-2` | 论断式标题：二级标题须含判断（动词/形容词/比较/因果），不得为纯名词短语 | 标题含 `：`、`——`、`，` 之一，或含判断词 |
| `S-3` | 一段一义：单段 80–250 字，不超过 300 字 | 段落中文字符数 |
| `S-4` | 数字必带三件套：口径、期间、来源锚点 | 关键数字后 20 字内出现 `（口径，期间，文件 pXX）` |
| `S-5` | 三类数字分列：历史事实／文件预测／独立假设，不得同列 | 表格表头或行标注类型 |
| `S-6` | 图表密度 ≥ 每 2,000 字 1 张，且每张有 `资料来源` | 计数 |
| `S-7` | 分级表达：`已证实 / 证据不足 / 无法判断 / 不可比 / 不可得`，不用状态码 | 正文不出现 `CONFIRMED` 等 |
| `S-8` | 克制"我们认为"：全文 ≤3 次，且只用于与共识相反的判断 | 计数 |
| `S-9` | 不写过程：不出现"本报告的处理是""初稿写…本版改为""经核对后……" | 禁用词表 |
| `S-10` | 风险必带传导链：机制 → 证据 → 触发条件 → 财务影响 → 监测指标 | 五要素齐全 |

## banned_patterns

正文出现任一即判 `FAIL`。附录不受限。

| 类别 | 模式 | 例 |
|---|---|---|
| 流程编号 | `FLOW #\d+`、`§\d+\.\d+（FLOW`、`Step \d` | "资产清单与权属（FLOW #8）" |
| 状态码 | `CONFIRMED`、`PARTIALLY_SUPPORTED`、`INDETERMINATE`、`NOT_COMPARABLE`、`SOURCE_UNAVAILABLE`、`DATA_QUALITY_WARNING`、`UNDEFINED_THRESHOLD` | "估值判断 `PARTIALLY_SUPPORTED`" |
| 测试语 | `PASS`、`FAIL`、`断言`、`自检通过` | "三类型数字是否混列 PASS" |
| 内部标尺 | `bands \d+/\d+`、`阈值档位`、`低位（bands` | "中位（bands 95/90）" |
| 修订语 | `初稿`、`本版`、`上一版`、`修订说明`、`更正清单` | "初稿把 DT51 当作……" |
| 运行语 | `run_log`、`执行 skill`、`按 FLOW 执行`、`产出物` | "执行 skill v1.0.0" |
| 元话语 | `本报告的处理是`、`需要说明的是`、`必须指出`（连用 ≥3 次/节） | — |

## figure_table_policy

| 项 | 规则 |
|---|---|
| 编号 | `表 1`／`图 1`，全文连续，不按章重排 |
| 标题位置 | 表在上、图在下；标题在图表**上方** |
| 资料来源 | 每张必写，格式 `资料来源：{披露文件}、{数据库}、本报告整理` |
| 自算图表 | 资料源须写"本报告整理"，不得伪装成披露数据 |
| 数据表上限 | 正文数据表单表不超过 12 行；超出拆表或移附录 |
| 禁止 | 只罗列字段的"机械表"（如把招募书的产品要素表原样搬入正文）——这类表移附录 |

## word_count_policy

| 项 | 定义 |
|---|---|
| 计数对象 | 中文字符（`[\u4e00-\u9fff]`） |

| 不计入 | 封面、目录、附录、参考文献、来源索引、运行日志、自检表、版本变更记录 |
| 分别报告 | 中文正文字符数／英文字母数／数字字符数／Markdown 总字符数，四项分开，不得合并称"字数" |
| 投前下限 | **≥15,000** 中文正文；目标 17,000–20,000 |
| 投后下限 | ≥3,000 中文正文（不设上限） |
| 反注水 | 连续 30 字以上与另一段完全重复即判重复；同一表格出现两次即判重复 |
| 工具 | `python tools/count_report_words.py <report.md>` |

## review_checklist

### 第一轮：内容与逻辑（`R1`）

| id | 检查项 | 不通过示例 |
|---|---|---|
| `R1-1` | 每条结论都能在正文找到至少 3 个支撑数字 | "资产质量优秀"无数字 |
| `R1-2` | 每条重要结论都有反面证据或不利解释 | 只写优点 |
| `R1-3` | 收入 → EBITDA → 可供分配的传导有量化 | "成本控制良好"无数 |
| `R1-4` | 估值参数被独立评价，不是照抄 | "折现率 5%，合理" |
| `R1-5` | 分派率与 IRR 分开表述，且给出计算过程 | 只给结果 2.67% |
| `R1-6` | 情景含悲观，且悲观情景有触发路径 | 只做中性 |

| id | 检查项 | 不通过示例 |

| `R2-5` | 图表密度达标，且每张有资料来源 | 5,000 字 0 图 |

## quality_states

| `SOURCE_UNAVAILABLE` | 该材料未公开披露 |
| `DATA_QUALITY_WARNING` | 披露口径存在问题 |
| `UNDEFINED_THRESHOLD` | 缺少可参照的阈值 |

<<<FILE: FLOW.md>>>
--{abstract}--
思考路径：
1. 写作不是取数流程的复述。取数流程回答"我怎么知道这个数"，报告回答"因此该不该买"。两者的骨架不同，硬套会得到一份工序单。所以第一步是换骨架，不是润色句子。
2. 换骨架之前先定论点。一份报告只有一条主论点，主论点下面三条支柱，每条支柱必须能说出相反的证据。支柱立不住，章节再多也是空的。
3. 章节是论点的展开，不是数据的分类。"运营情况"是数据分类，"出租率修复靠降价换来，且降价尚未结束"是论点展开。标题写不成论断，说明这一节还没想清楚。
4. 正文与附录的分界线是：读者需要用来做判断的，进正文；用于让同行复核的，进附录。口径裁决、自检结果、纠错记录属于后者——它们很重要，但不该占据投资经理的前 30 屏。
5. 语言清洗是独立工序。写完再洗比边写边洗有效，因为写作时会不自觉地用"本报告的处理是"这类自我指涉的句子，这些句子只有在通读时才会暴露。
6. 字数不是目标。字数不足说明论证不足——通常是缺机制、缺反证、缺敏感性、缺可比对照。补这四样会自然涨字数，补形容词只会在审稿时被删掉。
7. 两轮审稿必须分开做。第一轮只看"这个判断站不站得住"，第二轮只看"读者读不读得下去"。混在一起做，两件事都做不深。
