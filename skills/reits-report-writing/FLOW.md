--{abstract}--
将研究结果组织成通用于不同公募 REITs 的报告：结论有证据，参数有依据，测算可复核，判断带档位。章节按读者的问题组织，不复制执行工序；不得套用历史案例结论。用记者腔写——主语是人与钱，不是"本报告"；每个数字带参照系。投前中文正文不少于 15,000 字符，投后不少于 3,000 字符，横向基准按内容需要不设下限；专题按任务约定，均不设上限。计数不含封面与附录，篇幅用于解释而非重复。
--{/abstract}--

# Step 0：输入与论点

#1 --{动作}-- [非数据]
**核验上游研究结果，连判断档位一起核**
- 检查事实、模型、假设、结论证据和来源索引；可沿用等价底稿，不为文件形式重复造表。
- 横向基准报告另核 `findings.csv`：每行是否带判断、**用词档位**、证据锚点、反例、指回坐标。缺档位的行不能直接用——先回上游补，不许在本层按语气补。
- 区分历史事实、文件预测和独立假设，关键数字可定位原文或模型。
- 非核心资料缺失时明确限制并继续可支持的写作；核心缺口退回补证，无法补齐时限定受影响结论并标为部分完成，不机械阻断全部写作。影响判断的缺口及证据边界须在正文说明，不用文字掩盖缺失。
[输出]：可写范围与缺口

#2 --{动作}-- [非数据]
**确定主论点与依据**
- 说明资产是什么、价值是否成立及其原因；支撑论点数量按证据确定。
- 检查重要判断的不利证据和失效条件，不强造反证。
[输出]：主论点及支撑依据

#3 --{动作}-- [非数据]
**组织章节与读者的问题**
- 按 `outline_schema` 选骨架：投前用 `pre`、投后用 `post`、横向基准用 `comparison`。三套骨架的问题清单不同，不得混用——横向基准套 `pre` 会写出"值不值得买"，那不在它的能力范围内。
- 每章回答一个问题，问题写成疑问句；答不出就删章或并章。
- 必要的背景和法律说明保留，但不因"每章都要有判断"而强造因果。
[输出]：报告提纲（章 → 疑问句）

#4 --{动作}-- [非数据]
**确定清晰标题**
- 标题准确反映内容；证据充分时用判断式标题，法律、结构和计算说明可用描述式标题。
- 不强制标题格式、长度或论断比例，不把相关变化写成未经证明的因果。
[输出]：章节标题

#5 --{动作}-- [非数据]
**撰写自足摘要**
- 概括投资对象、现金流来源、主要分歧、估值和价格条件、回报边界及关键风险。
- 说明结论及前提；无需固定占比或逐问限句，不依赖后文章节引用。
[输出]：投资摘要

# Step 1：正文与证据

#6 --{动作}-- [非数据]
**展开分析与计算**
- 按结论、证据、机制和投资含义展开，篇幅服从问题；法律判断可由条款支撑，不要求每节凑数字或反证。
- 现金流及估值章节在正文展示关键公式、参数、参数合理性、逐项计算及结果，并解释披露复算与独立测算差异。
- 风险收益比较在同一情景下展示现金分派、价值变化、可测总回报和风险触发条件；证据不足说明影响。
[输出]：完整正文

#7 --{动作}-- [数据]
**标明数字类型与口径**
- 历史事实、文件预测、独立假设可同表比较，但须分列或逐行标明类型、期间、单位、来源和分母。
- 区分资产/基金价值、可供分配/实际分派、分派率/总回报；不得在写作时新造数字，需新增测算则返回模型。
[输出]：可追溯的数据展示

#8 --{动作}-- [非数据]
**配置必要图表**
- 按表达需要使用结构图、租约到期图、现金流桥接和情景表；不设数量配额或固定行数上限。
- 图表连续编号，标注来源、期间及自算属性；核心测算不因表长而全部移附录。
[输出]：正文图表

#9 --{动作}-- [非数据]
**清理语言与过程记录**
- 正文用自然语言说明证据限制，删除流程编号、状态码、修订经过及空泛套话。
- 删除自指与读者语：`本报告`、`本文`、`本篇`、`读者可以`、`需要说明的是`、`值得注意的是`、`综上`。判据不是词频，是这句在说"我"还是在说"它"。
- 来源标注可保留必要的"本报告测算"，但每出现一次就问：换成"按 2025 年报重算"是否更具体。可以换的一律换。
[输出]：清晰可读的正文

#10 --{动作}-- [非数据]
**记者腔改写：把"本报告如何处理"改成"谁因为什么多赚少赚"**
- 逐段问一句：念给没看过材料的人听，他能不能说出"谁受损、谁受益、大概多少"。说不出的是方法论述，移附录或删。
- 六种必改：**自指**（"本报告回答三件事"→直接给三句判断）；**邀读者核对**（"读者可以不同意"→直接陈述选样事实）；**判决交给本报告**（"本报告倾向"→"我们倾向"）；**形容词结论**（"质量相对较弱"→位次＋幅度＋与第一名差）；**裸数字**（"减值 7,152 万"→"相当于全年可供分配的 41%"）；**清单体**（整节"第一第二第三"→一段一个因果）。
- 三条机械动作：**换标测试**（把标的换成另一只仍成立＝没有信息量，删）；**删首段**（交代背景、定义概念、复述前文的，整段删）；**删尾句**（"综上所述""由此可见"一律删）。
- 必要的口径说明不算废话，但要降到括号、图注或附录，正文最多留一句"（口径见附录）"。判据：删掉它结论是否仍成立。
- 全篇"我们"只用于三件事：给倾向、承认不知道、承担测算。每千字不超过一次；超出说明在替读者下结论，停下重写。
- 跑一遍 `python tools/check_voice.py <report.md>`：自指语与读者语应清零，裸数字逐条补参照系。工具只报位置不判风格，命中后人工决定删或补。
[输出]：记者腔改写后的正文

# Step 2：复核与交付

#11 --{动作}-- [数据]
**检查结构和重复**
- 检查必需主题有无遗漏、摘要能否独立理解、论证及术语是否清楚，删去重复、跳跃推理和无关背景；直接修正正文，不另建检查记录。
- 字数建议仅用于分配篇幅，不按标题样式、段长或章节配额机械判失败。
[输出]：结构与表达修正后的正文

#12 --{动作}-- [数据]
**核验正文长度**
- 运行 `python tools/count_report_words.py <report.md>`，分别记录中文正文、英文字母、数字字符和总字符数。
- 投前中文正文至少 15,000 字符，投后至少 3,000 字符，均不设上限；专题按任务约定。不足时补证据、机制与测算，不靠附录或重复扩充。
- 详细指标保留在 `report_metrics.json`，首页只需说明正文长度与口径。
[输出]：字数指标

#13 --{动作}-- [数据]
**核对数字与结论**
- 正文关键数字与权威模型及底稿对账；冲突时查明来源并修正，不盲从旧底稿。
- 从正文参数与公式复算关键结果；披露值、复算值、独立值及不同现金流层级分别核验。
- 核查来源、参数合理性、估值层级与风险传导是否支持结论；预测 IRR/XIRR 可使用明示的期限和日期假设，资料不足时限定结论。
[输出]：完成必要核验并修正的报告

#14 --{动作}-- [数据]
**交付与归档**
- 交付报告和字数指标；附录保留必要来源、公式及假设。影响判断的未解决问题须在相关正文说明，核心问题未解决时标注部分完成。
- 不要求固定审稿轮次，不生成独立 review 文件；必要核验在 #11–#13 完成，历史版本交给 Git 保存。
[输出]：报告与字数指标
