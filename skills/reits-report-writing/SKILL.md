# 公募 REITs 研究报告写作

本 skill 是一个 flow（可执行写作流程），**处在取数层的下游**。

**它解决的是一个问题**：三个业务 FLOW 跑完之后，手上有一堆正确的数字、一个可重算的模型、一张假设表，但写出来的东西读起来像运行日志。原因是**取数流程的骨架（Step 0 → 分层 → 归因 → 测算 → 估值 → 结论）与投研报告的骨架（投资问题 → 论证 → 判断）不是同一个东西**。把 FLOW 的步骤名当章节名，就等于把工序单交给了客户。

**执行方式**：阅读同目录下的 FLOW.md，按 `#1 → #15` 顺序执行。`#1` 做输入准入，`#2` 定论点树，`#3`–`#4` 定骨架与标题，`#5`–`#8` 写内容，`#9`–`#12` 清洗与核验，`#13`–`#14` 两轮审稿，`#15` 交付。

**运行前检查**：
1. 上游 FLOW 的产物必须齐备：事实底稿、模型、假设登记、claim 裁决表、来源索引。缺任何一项，先回上游补齐，不要用"文字补"掩盖"数据缺"。
2. 报告里的每一个数字必须能在上游产物里找到，**不允许在写作阶段新造数字**。需要新数字时，退回上游算，不许在正文里"估一个"。
3. 结论先于文字。`#2` 的论点树没定下来之前，不写任何一段正文。

**输出位置**：上游约定的 `outputs/{case}/`，文件名沿用既有命名（`report_{code}.md`）。同时产出 `report_metrics.json`（字数、图表数、禁用词命中数），供自动化测试读取。

## 这个 skill 回答什么

**不是"怎么把话说完整"，是"怎么让一个没读过原始材料的人，在 15 分钟内做出买或不买的判断"。**

所以必须做到三件事，缺一不算完成：

1. **结论在前，且是判断不是描述。** 第一章读完必须知道：这是什么、赚什么钱、值不值、什么情况下不值。
2. **每一节回答一个投资问题。** 节标题是论断，不是话题。"行业现状""运营情况"不是论断；"出租率修复靠降价换来，且降价尚未结束"是论断。
3. **过程与结论分离。** 自检、口径裁决、纠错、数据缺口属于附录。正文只留论证。

## 三条硬约束

- **正文不出现流程编号与状态码。** `FLOW #n`、`run_log`、`PASS/FAIL`、`CONFIRMED`、`bands 95/90` 一律不得进入正文，只能出现在附录的执行记录或 claim 表里。
- **不写"我做了什么"，只写"事实是什么、意味着什么"。** "本报告的处理是双列并行" → "两个口径都保留：判断收现能力用四季加总，判断全年现金生成用年报数"。
- **不注水。** 字数不够时补的是**论证**（机制、反证、敏感性、可比对照），不是形容词与重复。判据：新增的每一段，删掉之后结论会变弱——如果删掉结论不变，那段是水。

## 与上游 FLOW 的接口

| 上游产出 | 本 skill 的用法 | 不得做的事 |
|---|---|---|
| `facts.yaml` / 数据矩阵 | 正文所有数字的唯一来源 | 不在正文里重算上游已算过的数 |
| `model/cashflow.xlsx` | 情景与敏感性的数来自这里 | 不在正文里手改模型结果 |
| `assumptions.csv` | 每条假设进附录登记表；正文引用时标注"假设" | 不把假设写成"披露" |
| `claims_verdict.csv` | 裁决结果进正文的结论句，`claim_id` 与状态码进附录 | 不在正文里展示 `claim_id` |
| `source_index.csv` | 附录的来源索引；正文用"文件 + 页码"锚点 | 不用"据披露"这类无锚点表述 |

## 学谁的行文

本 skill 的文风规则来自对 11 份卖方行业深度报告（`_ref/202608研报/`，408 页、327 张图表）的结构统计，主要可迁移的四条：

1. **首页"投资要点"4–6 条，每条一个完整论证**：`结论句。论据（数字＋同比＋时间）。含义。` 最后一条固定是投资意见，倒数第一条固定是风险提示。
2. **二级标题 41% 带冒号或破折号，后半句是判断**：「底部特征：钢企利润情况基本处于历史底部」「景气回落的原因——地产需求疲弱，但边际影响预期弱化」。
3. **图表密度约每 1.25 页一张**，每张图下方必须写 `资料来源：A、B、本报告整理`。
4. **"我们认为"是稀缺词**，11 份报告平均只用 1.3 次，且几乎都出现在与市场共识相反的判断处。滥用会稀释它。

统计口径与原始记录见 `template/report_style_analysis.md`。
