# 公募 REITs 投后定期跟踪

本 skill 是一个 flow（可执行分析流程）。

**执行方式**：阅读同目录下的 FLOW.md，按 `#1 → #22` 顺序执行。`#5` 产出的 `dataset/panel.parquet` 与 `dataset/panel.csv` 是后续所有动作的唯一数据来源；**任何后续动作不得自己再读 PDF、再换算单位、再对齐期间**。

**运行前检查**：
1. METADATA.md 的 `inputs` 五项必须由用户确认：`fund_code`、`start_period`、`end_period`、`focus_period`、`doc_root`。
2. `data_requirements` 中 `execution_required: true` 的条目必须已通过 `#4` 的 source 探测；未通过的，在报告首页写明 `SOURCE_UNAVAILABLE` 并在对应表格留空，不得用估算填充。
3. 若 `end_period` 之后没有已披露的定期报告（正常情况：季度报告在季后 15 个工作日内披露），以最后一期已披露为准，并在报告首页写"数据截止期"。

**输出位置**：`<doc_root>/../output/YYYYMMDD_HHMMSS/`（可在 METADATA.md 的 `output_dir` 修改）。交付 7 项 + 一个不单列的 `charts/` 附属目录，清单见 FLOW `#22`。图表必须内嵌在报告正文里，不得作为独立产物单独交付。

**交付前必跑两个校验**（只依赖标准库，退出码非 0 不得交付）：

```bash
python tools/check_panel.py --panel <output>/dataset/panel.csv
python tools/validate_output.py --output <output> --doc-root <doc_root>
```

前者查面板结构（主键唯一、锚点格式、`*_cum` 单调），后者查产出契约（`doc_index.csv` 与 `source_index.csv` 的外键、页码上界、自算公式、URL 回验、正文锚点覆盖、panel 落盘位置）。
**文字规范不等于校验**：没有可执行脚本时，同一错误会在每次运行里重犯。

---

## 这个 skill 回答什么

**不是"这期业绩好不好"，是"招募说明书与上一期自己说的话，这一期兑现了没有"。**

三件事必须同时成立，报告才算完成：

1. **发生了什么** —— 三层矩阵（运营 / 区域 / 收入与可供分配），带原始值、单位、口径、页码。
2. **为什么发生** —— 归因落到"哪个资产、什么原因、影响多少"，原因分五类：行业需求、客户流失、租约到期、竞争加剧、资产自身。
3. **接下来看什么** —— 明确列出下一期的验证指标与触发阈值，而不是泛泛的"需关注"。

## 三条硬约束

- **可供分配 ≠ 实际分派**。可供分配金额是当期经营产生的可分金额（含调整项），实际分派是宣告/实施金额（含上年结转、时点差）。两者不可互换，不可用"分派率"倒推经营质量。报告中出现"分红率"字样时，必须注明分子分母口径。
- **缺数据不补、不猜、不插值**。`NA`、`0`、`未披露`、`不适用`、`SOURCE_UNAVAILABLE` 五种状态严格区分。出租率缺失时不许写"基本稳定"。
- **累计与单季必须显式换算**。仅在原始披露为累计口径时做差分，公式写入 `formula_registry`；原始已给单季的直接用原始值，不得再差分一次。

## 与旧模板的差异（继承关系说明）

继承附件的四件套命名、YAML frontmatter、`--{abstract}--`、`#N --{动作}-- [数据|非数据]`、`[输出]/[输出示例]`、METADATA 原字段名。

针对 REITs 场景新增（均在 FLOW 中实际使用）：
- `period_semantics`：声明每个字段是时点值/期间累计/单季，供 `#5` 统一换算。
- `metric_bands`：出租率、租金同比、收缴率、WALE 的档位标尺，避免"高位/低位"无标尺。
- `claim_schema`（v2，14 列）：可证伪表述的台账。四类来源封闭（契约义务/招募书预测/管理层表述/扩募评估），**按关键词与可核查项规则抽取，不按裁量挑选**，同一批文件必得同一张表；`claim_id` 由文件名与陈述的哈希生成，跨期稳定；裁决六态机械判定（`CONFIRMED` / `REFUTED` / `PARTIALLY_SUPPORTED` / `INDETERMINATE` / `NOT_COMPARABLE` / `SUPERSEDED`），判据见 METADATA 的 `verdict_rules`。
- `formula_registry`：累计差分、单位换算、可供分配调整项的公式与生效期。

## 判读口径（经验规则，写入 FLOW 时不得省略）

- 出租率与租金同时下行 → 先查是否"以价换量"（新签单价 vs 续签单价），不是直接判经营恶化。
- 收缴率 >100% → 通常是回收前期欠款，不代表当期收现能力提升，需与应收账款余额同看。
- 剩余租期（WALE）缩短 + 到期集中 → 下一期续租风险前置，需列到期面积与租户。
- 可供分配金额同比与 EBITDA 同比方向背离 → 查调整项（资本性支出预留、应收应付变动、预收租金）。

--{abstract}--
思考路径：
1. REITs 的定期报告是"三张表 + 一堆运营表"，但判断的顺序不是报表顺序。先看运营（出租率、租金、收缴率、剩余租期），因为运营是收入的因；再看区域（哪个项目在拖，为什么），因为整体数字会掩盖分化；最后看收入与可供分配（钱有没有真收到、能不能分）。
2. 累计与单季是这类报告最容易出错的地方。Q2 单季 ≠ 半年报数字，必须 H1−Q1；但若原件已给单季，再差分一次就是重复扣减。所有换算进 Step 0，一次算清，后续只读标准面板。
3. 可供分配金额 ≠ 实际分派金额。前者是经营产生的可分金额，含资本性支出预留、应收应付变动等调整项；后者是宣告与实施金额，含上年结转。用后者判断经营，会把分配节奏当成经营改善。
4. 区域归因不能停在"某某项目出租率下降"。必须给出五类原因之一（行业需求/客户流失/租约到期/竞争加剧/资产自身），并给出证据；证据不足就写"未披露"，不写"可能"。
5. 每个"高/中/低"都要有 bands 来源。没有来源就输出 UNDEFINED_THRESHOLD，宁可不出档位。
6. 最后落在"下一期看什么"：具体指标 + 触发阈值 + 到期面积。没有这一节，报告只是复述。

# Step 0：Data Ingestion & Preprocessing

#1 --{动作}-- [数据]
**建立披露文件清单并校验完整性**
* 数据依赖：doc_root 下的全部 PDF
- 按文件名解析 `披露日期 / 类型标签 / 报告期`，类型标签取值：`q` 季报、`h` 半年报、`y` 年报、`yunying` 运营数据公告、`zmsms` 招募说明书、`pg` 评估报告、`sj` 审计报告、`fl_yijian` 法律意见书
- 覆盖 start_period 到 end_period 的每个报告期，检查是否存在：季报 4 期、半年报 1 期、年报 1 期、年度评估报告、年度审计报告、招募说明书、法律意见书、运营数据公告（如有）
- 校验 PDF 可解析（页数 > 0 且可提取文字）；扫描件无文字层时标 `NO_TEXT_LAYER`——**评估报告、法律意见书常为扫描件，不要假设有文字层**
- 缺失文件如实登记，不得用其他期次替代
[输出]：披露文件清单 `dataset/doc_index.csv`

> **落盘要求**：清单必须写成文件 `<output>/dataset/doc_index.csv`，字段固定为
> `file, type, tag, period, disclose_date, pages, text_layer, status, url, local_path`。
> `file` 是**完整文件名（含 .pdf）**，它同时是 #22 `source_index.csv` 的外键父表；
> `tag` 只是机器标签（q2026Q3 / y2025），不能替代 `file` 出现在来源索引里。
> 离线场景（doc_root 已有 PDF、无公告接口）`url` 写 `NA(offline)`，`local_path` 写相对 doc_root 的路径。
> 只把清单写进 run_log 而不落盘，会让 #22 失去可引用的文件主键——这是可复现性最常见的断点。

> **前置校验 A：枚举必须逐分类进行，不得只查一个入口。**
> 基金公告接口按分类返回，**定期报告与基金文件不在同一分类**。只查"基金文件"一类，会拿到招募书、合同、托管协议，但**拿不到任何季报/年报**；反过来只查定期报告，会漏掉法律意见书。
> 每一步必须记录**每类返回多少条、命中多少条**，条数为 0 的分类要写明"该分类确实为空"还是"接口未返回"。
> 反例（真实发生）：只调用单一分类，11 份材料里缺了 2025Q1、Q2 季报，报告却按"只有两季"写了窗口限制——**限制是假的，是取数漏了**。

> **前置校验 B：来源链接必须回验基金代码。**
> 每条记录若带原始公告 URL，必须校验 URL 中的代码等于标的代码。
> 反例（真实发生）：某案例 11 条记录的 URL 全部是另一只基金的代码，文件内容正确但链接全错；按索引核对会得出"文件与报告不符"的错误结论，**而真正错的是索引**。

#2 --{动作}-- [数据]
**抽取三张表与运营表原始数值**
* 数据依赖：营业收入、净利润、经营活动现金流净额、可供分配金额、实际分派金额、期末出租率、期末租金单价、期末租金收缴率、期末加权平均剩余租期
- 逐文件定位：利润表、现金流量表、可供分配金额计算表、基础设施项目运营情况表
- 每条记录必须带 `文件 p页码 表名/小节` 锚点
- 数值原样保留（千分位、括号负数、单位），不在本步做任何换算
[输出]：原始值长表 `dataset/raw_extract.csv`

> **前置校验 C：单季与累计必须由字段名承担，并用单调性验证。**
> 季报 §3.1「主要财务指标」只披露**本期**数（= 单季），**没有本年累计收入**；§3.3.1「可供分配金额」才同时给出"本期"与"本年累计"。
> 命名：单季 `_q`，本年累计 `_cum`。
> 校验：同一指标、同一维度、同一年度内，`_cum` 序列**必须单调不减**——累计值不可能下降。若出现下降，几乎一定是把单季数标成了累计。
> 后果量级（真实发生）：某基金 2025Q4 的 `revenue_cum` = 2,462 万元，按名字会读成"全年收入"，实际全年为四季之和 **1.115 亿元，差 4.5 倍**。
>
> **前置校验 D：季度加总必须与中期/年度报告对账。**
> `Q1 + Q2` 应等于中期报告的 H1；`Q1 + Q2 + Q3 + Q4` 应等于年报的 FY。
> 不符时**记录差额并双列并行**，不得静默采用其中一个数。
> 反例（真实发生）：某案例 H1 现金流写作 58,616,560.98 元，而中期报告原文是 37,588,381.33 元、且恰等于 Q1+Q2——前者在全部 58 份原始文件中都找不到，属误录。
> 另一案例：四季现金流加总 83,167,187.30 元 vs 年报 83,656,185.80 元，差 0.59%（48.9 万元），系年报审计调整——**这是真实差异，要写出来，不能抹平**。

#3 --{动作}-- [数据]
**字段映射、单位与频率统一**
* 数据依赖：`raw_extract.csv`
- 映射到标准字段名（见 `#5` 数据字典），单位统一为：金额→元、面积→平方米、单价→元/平方米/月、比率→%
- 百分比统一为 0–100 数值，不混用小数
- 频率统一为季度；时点类指标归属到季末日期，期间类指标归属到报告期标签
- 同一指标在不同文件出现且不一致时，优先级：年报 > 半年报 > 季报 > 运营公告，并在 `conflict_log.csv` 记双方
[输出]：映射后宽表 + 冲突日志

> **前置校验 E：同一份报告里出现两个口径时，两个都要取，不许只留一个。**
> 运营指标的"时点值"与"可解释值"经常同时出现在同一段：期末出租率受月末单日扰动，报告会额外给出"考虑披露日前已起租面积"的口径。两者**不是同一个东西，也不是谁替代谁**。
> 处理规则：
> 1. 趋势序列用**时点值**（与其他各季同口径，可比）；
> 2. 归因与解释**两个都用**（时点值说明月末真实空置，可解释值说明常态经营水平）；
> 3. 差值单独列出——**差值本身就是信息**，它度量了"时点噪声"有多大。
> 反例（真实发生）：某季出租率时点值 81.26%、已起租口径 88.69%，差 7.43pct。只取 81.26% 会写成"出租率断崖下跌 11.68pct"，实际是**单个租户换签搬仓造成的一个月末空档**；只取 88.69% 则掩盖了月末真实空置。
> **若只抽到一个口径，必须回原文确认是否另有一个被漏掉。**

[输出示例]：

| 2025Q2 收入 | 21,340.1 万（半年报差分） | 21,290.5 万（Q2季报） | 21,290.5 万 | 季报为原始披露，优先 |
| 2025Q3 出租率 | 81.26（期末时点） | 88.69（含已起租） | 序列用 81.26，归因并列 88.69 | 同报告双口径，非冲突 |

#6 --{动作}-- [非数据]
**建立/更新 claim 台账**
* 数据依赖：`dataset/doc_index.csv`、四类披露原文（基金合同、招募书、定期报告、扩募/评估报告）
* 权威定义：METADATA 的 `claim_schema`（v2，14 列）。本节只讲怎么抽，不重定义字段。

**抽取是规则动作，不是判断动作**：给定同一批披露文件，任何人跑出来必须是同一张表。四步固定执行：

1. **切句**：按「。」「；」把候选文件正文切成句，保留原文与页码（页码取 `=== Pn ===` 锚点）。
2. **过桶**：逐句匹配四个来源桶的关键词（S1 契约义务 / S2 招募书预测 / S3 管理层表述 / S4 扩募评估），桶外一律丢弃。
3. **过可核查项**：句内必须同时出现数字、出租率、租金、分派、面积、期限之一。只命中关键词而无指标者丢弃——「提升运营效率」这类不得入库。
4. **去重截断**：同一 `indicator` 在同一文件内只留最新一条，旧的标 `SUPERSEDED`；总数上限 12 条，超限按 S1→S4 优先级截断，截掉的条目写进 `run_log.md`。

- `claim_id = "C-" + sha1(归一化文件名 + "|" + 归一化陈述)[:6]`，同一句话跨期重跑 ID 不变；`seq` 只是展示序号，按页升序重排，**不得用序号做引用的依据**
- `statement` ≤60 字，去主观前缀但不得改写语义；`quote` ≤40 字逐字摘录，不得转述
- `judgment_rule` 五选一（`threshold_gte` / `threshold_lte` / `each_period_eq` / `monotonic` / `direction_only`），`rule_param` 必须来自原文数字
- 原文没给量化阈值时**不得用行业惯例代填**，只能降级为 `direction_only` 并注明「原文未给量化阈值」
- 首次运行全量抽取；后续运行沿用台账只做裁决；新增披露文件时增量追加，不改既有 `claim_id`
[输出]：`claims_<code>.yaml`（台账，跨期沿用，只增不改）
[输出示例]：字段顺序见 `claim_schema.columns`，示意前 8 列

|---|---|---|---|---|---|---|---|

# Step 5：裁决与风险

#20 --{动作}-- [数据]
**claim 逐条裁决**
* 数据依赖：`claims_<code>.yaml`、`dataset/panel.csv`
* 裁决是**确定性动作**：给定 `judgment_rule` 与 `panel` 取值，结果唯一。同样的台账跑两次必须得到同一张表，不得因叙事需要调整。

- **前置校验：分母口径三问**（未答完不得进入裁决）
  1. claim 的阈值是哪个口径下给的？（招募书预测 / 实际·募集规模 / 实际·期末市值 / 实际·评估值）
  2. 观测值的分母与阈值的分母是否同一口径？不同则先换算，换算不可行则判 `NOT_COMPARABLE`
  3. 若分母随市场变化（市值），该 claim 是否只适用于"投资者实际收益率"而非"是否达标"？
- 按 `aggregation` 取值：`each_period` 逐期执行；`mean` 取均值后执行；`latest` 只取目标期
- **六态判据，对号入座，不得叠加主观修饰**：

| 态 | 机械条件 |
|---|---|
| `CONFIRMED` | 所有观测期满足规则，且观测期数 ≥ 声明覆盖期一半 |
| `REFUTED` | 任一观测期明确违反规则 |
| `PARTIALLY_SUPPORTED` | 方向一致但幅度未达 `rule_param`；或 `direction_only` 且方向正确 |
| `INDETERMINATE` | 观测期未到 / 指标未披露 / `rule_param` 缺失 / 只有定性无量化 |
| `NOT_COMPARABLE` | 分母口径不同且不可换算，须在两处写清具体数值 |
| `SUPERSEDED` | 同一 `indicator` 已有更新表述，旧条目不参与本期裁决 |

- `direction_only` 永远不得判 `CONFIRMED`——没有数字就没有达标可言
- 判 `REFUTED` 必须能指到具体的观测期与取值；指不到就是 `INDETERMINATE`
- 数据缺失导致无法裁决的，写清缺哪个指标、缺哪期、影响哪条结论
- 规则与聚合方式不得在裁决时临时更改；确需更改的，回写台账（新增条目，旧条目标 `SUPERSEDED`），不得原地改写
- **反例（必须避免）**：用年报的市值口径分派率（4.36%）去对标招募书的募集规模口径预测（4.81%），会得出"未达预测 0.45pct"的错误结论。溢价交易时市值口径必然低于募集规模口径，与经营好坏无关。
[输出]：`claims_verdict_<code>.csv`（14 列，与台账同名同序）
[输出示例]：节选关键列
| seq | claim_id | statement | observed | verdict |
|---|---|---|---|---|
| C1 | C-3f9a1c | 应将 90% 以上年度可供分配金额分配 | 2025 年归属分派 3.423 亿 ÷ 可供分配 3.352 亿 = 102.1% | CONFIRMED |

**来源索引硬规范**（`source_index_<code>.csv`，utf-8-sig，主键 `source_id`）

| 字段 | 必填 | 规则 |
|---|---|---|
| `source_id` | 是 | `S0001` 递增；正文锚点引用此列 |
| `file` | 是 | **必须是 `doc_index.csv` 的 `file` 原值**（完整文件名含 `.pdf`），外键；禁止填 `q2026Q3` 这类标签 |
| `local_path` | 是 | 相对 `doc_root` 的路径；离线场景唯一定位手段 |
| `url` | 是 | 原始公告 URL；无则写 `NA(offline)`，不得留空；非空时须含基金代码 |
| `page_from` / `page_to` | 是 / 否 | 整数，`1 ≤ page_from ≤ page_to ≤ doc_index.pages`；单页缺省视为等于 `page_from` |
| `section` | 是 | 原文小节号或表名，如 `§4.1.2 整体运营情况` |
| `metric` | 是 | 与 `metric_naming` 的 base 对齐 |
| `value` / `unit` | 是 | 原文数值与原文单位，不在本步换算 |
| `kind` | 是 | 枚举：`披露原值` / `披露原值（期间均值）` / `披露原值（年初至今）` / `自算` |
| `computed` / `formula` | 是 / 条件必填 | `computed=是` 时 `formula` 必填，写明输入列名与口径 |

**五条硬校验，一次跑完才允许交付**（`tools/validate_output.py`，仅依赖标准库）：

1. C1 外键：`source_index.file` 集合 ⊆ `doc_index.file` 集合
2. C2 页码：`page_to ≤ doc_index.pages`
3. C3 自算带公式：`computed=是` → `formula` 非空
4. C4 URL 回验：`url` 非空且非 `NA(offline)` → `url` 含 `fund_code`
5. C5 锚点覆盖：正文出现的每个 `<tag> p<page>` 锚点，能在 `source_index` 命中对应 `file` 且 `page` 落在 `page_from–page_to` 内

> 反例（真实发生）：某案例来源索引 42 行全部只写 `q2026Q3`、`y2025` 这类标签，未写文件名，
> 报告里每个数字都能定位到"某份季报第 12 页"，但无法定位到"哪份 PDF"——索引看似完整，回查仍要多跳一步。
> 同一案例的来源说明写"全部记录未带公告 URL，故未执行链接回验"，把前置校验 B 静默跳过而不是标注 `NA(offline)`。
> **校验不可执行 = 没有校验。** 引用 `tests/` 而未落盘该目录，同样算没有校验。
