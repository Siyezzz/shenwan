# 公募 REITs 投前深度分析

本 skill 是一个 flow（可执行分析流程）。

**执行方式**：阅读同目录下的 FLOW.md，按 `#1 → #26` 顺序执行。`#3` 产出的 `dataset/facts.yaml` 是全流程唯一事实源；`#14` 产出的 `model/cashflow.xlsx` 是全部测算的唯一模型。

**运行前检查**：
1. METADATA.md 的 `inputs` 必须确认：`fund_name`、`doc_root`、`analysis_date`、`discount_rate_scenarios`。缺 `discount_rate_scenarios` 时使用 `#18` 的默认三档并注明为研究假设。
2. `data_requirements` 中 `thesis_required: true` 的条目若在文件中取不到，报告中必须出现对应 `INDETERMINATE`，**不得用行业均值替代且不声明**。
3. 区分三类数字：`历史事实`（募集说明书披露的实际数）/ `文件预测`（评估报告或管理人预测）/ `独立研究假设`（本报告自设）。三者不得混列在同一列。

**输出位置**：`output/YYYYMMDD_HHMMSS/`（可在 METADATA.md 的 `output_dir` 修改）。产出 7 个文件，清单见 FLOW `#26`。

## 这个 skill 回答什么

**不是"这个产品好不好"，是"在什么价格上、什么假设下，这笔钱的分派回报能覆盖风险"。**

所以必须给三样东西，缺一不算完成：

1. **可复核的现金流模型** —— 参数有出处，公式可追溯，别人拿你的 Excel 能改一个假设看到结果变化。
2. **参数合理性判断** —— 不对评估报告的折现率、出租率、租金增长率照单全收，要给出自己的区间与理由。
3. **失效条件** —— 明确写出"什么情况下这个投资逻辑不成立"，而不是只写风险提示清单。

## 三条硬约束

- **可供分配 ≠ 可分派**。测算口径是"可供分配金额"（EBITDA − 资本性支出 − 税费 ± 调整项），分派率 = 可供分配 / 募集规模。若引用管理人的"预测分派率"，必须核对分母是募集规模还是评估值。
- **不做单点预测**。核心结论必须建立在情景（悲观/中性/乐观）之上，单点数字只能出现在中性情景。
- **历史、预测、假设三分**。每一行数字都要标注属于哪一类；无法归类的，标 `未披露`。

## 与旧模板的差异（继承关系说明）

继承附件四件套命名、YAML frontmatter、`--{abstract}--`、`#N --{动作}-- [数据|非数据]`、`[输出]/[输出示例]`、METADATA 原字段名。

针对投前场景新增（均在 FLOW 中使用）：
- `step0_required`：投前材料多、版本多（申报稿/反馈稿/封卷稿/更新稿），必须先做版本裁决，否则会拿旧稿的参数算新稿的规模。
- `assumption_register`：每条假设登记 `类别 / 取值 / 依据 / 敏感性`，防止假设混入事实。
- `valuation_params`：折现率、资本化率、增长率、期限的组合必须成组出现，便于敏感性。
- `scenario_set`：三情景定义写死在 METADATA，避免每次运行换一套情景。

## 判读口径（经验规则）

- 招募说明书的"预测可供分配"通常已扣除管理人报酬与运营管理费，但**未必扣除全部资本性支出**；核对时以"可供分配金额测算表"的调整项为准。
- 评估值高 ≠ 分派率高。评估值由折现率决定，折现率降 50bp 可抬估值 6%–9%，但现金流不变；因此"评估值/募集规模"与"分派率"必须同时看。
- 原始权益人自持比例高 + 有增持承诺 → 利益一致性较好，但不改变基础资产本身的现金流质量。
- 商业不动产（消费基础设施）与仓储物流的租金结构不同：前者常含提成租金，后者以固定租金为主。混用可比公司会得出错误结论。
