# 输出规范：报告九节骨架与硬性要求

## 一、总则

- 正文中文 ≥15,000 字符（`tools/count_report_words.py` 口径：不含封面、附录、来源索引）
- **图 5 张，必须嵌在正文里**，不能作为单独附件交付
- Markdown 版图走相对路径（GitHub 渲染）；HTML 版内联 SVG（单文件、离线可读）
- 所有图坐标由脚本从数据计算，**不手写像素**
- 每个关键数字带口径与锚点（页码/章节）

## 二、封面必备字段

| 字段 | 要求 |
|---|---|
| 报告类型 | 横向基准（peer benchmarking） |
| 本项目 | 代码 + 全称，多只时用「＋」连接 |
| 对标范围 | N 只 + 从 M 只候选池中筛选 |
| 比较时点 | 时点指标基准日 ＋ 期间指标年度，两者成对出现 |
| 资料截止日 | 明确到日 |
| 数据版本 / 图表版本 | 脚本名 + 产出文件名 |
| 中文正文字符数 | 实测值，不与全文混算 |
| 统计口径 | 一句话说明不含哪些部分 |

## 三、九节骨架

### §1 结论：本项目在市场中的位置

**必须回答**：三个坐标各在第几、这个名次稳不稳、差异的结构性来源是什么。

必含三段：
1. **三句话结论** —— 每句带限定（排第几 / 换口径后第几 / 极差多少）
2. **位置一览表** —— 六个以上维度，每行带"组内位置"与"判断依据（指向哪一节）"
3. **能回答什么 / 不能回答什么** —— 明确写出不给买入建议、不给总分、不给目标价，并说明原因（n 太小）

**反例**：「综合来看，本项目处于同类中游水平。」——没有坐标、没有口径、没有稳定性判断。

### §2 为什么是这几只

**必须回答**：候选池怎么来的、每只为什么进/出、边界动一动会改哪一句。

必含五段：
1. **三层收敛** —— 产品形态 / 资产类型 / 可执行条件，逐层说明
2. **候选池全量枚举** —— 10 只清单表，含结论与理由
3. **排除理由** —— 三级分类（期间不完整 / 披露不可得 / 类型不同质），每条带"为什么"
4. **边界检验** —— 至少 1 只被排除标的，四个数 + "会改哪一句"
5. **n 很小的自我约束** —— 不做分位、不做显著性、位次不是评分模型

**这一节是整份报告可信度的地基。** 缺了它，后面所有排名都是"我挑了几只我熟悉的"。

### §3 同一时点：时点与口径

**必须回答**：时点指什么、分母为什么这么选、哪几处口径必须对齐。

必含三段：
1. **时点 vs 期间** —— 两类指标分别取什么，哪些同比不可算
2. **分母为什么用反推市值** —— 三条理由 + 代价 + 为什么不用评估值
3. **五处必须对齐的口径** —— 表格：陷阱 / 表现 / 处理方式

必含一张"口径日志"表（可放附录），逐项说明换算方式与影响。

### §4 收益率：三个口径

**必须回答**：三个口径分别第一是谁、为什么、换口径后排名怎么变。

必含六段：
1. 为什么必须用三个口径
2. C1 逐只表 + 第一名为什么第一（分子构成）
3. C2 逐只表 + 换口径后的名次变化列
4. C3 逐只表 + 为什么它反映的是位置而不是效率
5. 排名极差表 + 斜线图（图 2）
6. **分派的钱是谁挣的** —— 差额拆解表，区分三种性质（会计时点差 / 往年结转 / 第三方补足）

**这一节最容易犯的错**：只报 C1 就下结论。必须三个都给，且给极差。

### §5 资产质量

**必须回答**：五个维度各是什么、四维位次多少、客户结构属于哪一类。

必含六段：
1. 五维定义 + **为什么集中度单列**（它衡量客户，不衡量资产）
2. 量价四象限 —— 出租率 × 租金同比，四种处境
3. 租约久期 —— 方向的双向性 + 剔除租期的稳健性版本
4. 客户结构 —— 三种性质（关联 / 市场化 / 产业），**不能按数值排序**
5. 减值 —— 唯一无法被运营数据掩盖的证据 + 两个陷阱
6. 位次表 + 热力矩阵图（图 3）+ 三重限定

**必含**：一只标的多套集中度全部列出（口径 + 户数双标注）。

### §6 收益率 × 资产质量

**必须回答**：本项目落在哪个象限、这个位置的含义、定价有没有反映质量。

必含五段：
1. 定位图（图 4）+ 四象限各自代表谁
2. 本项目两只：同象限为什么不同因（逐项对照表）
3. 相关性检验 —— 三对 r 值，`r > 0.7` 时禁止说"脱钩"
4. 残差表 —— 拟合式 + 每只残差率 + 三种解释分列
5. 一个反直觉发现（如"分散在下行期不是优势"）

**禁止**：用"排序不一致"论证"定价与基本面无关"。

### §7 商业模式

**必须回答**：六只分别怎么赚钱、模式优劣的条件是什么、本项目两只差在哪。

必含五段：
1. 四问框架（钱从哪来 / 谁在管 / 风险谁担 / 增长靠什么）
2. 六张卡片表
3. 收费结构 —— 费用率 × 运营强度是否匹配 + 浮动费执行结果
4. **条件式优劣对照表** —— 模式 / 代表 / 适用条件 / 代价 / 验证指标，不给总分
5. 本项目两只的模式差异表 + 一张两轴图（图 5）

**禁止**：打分、评级、"强/弱"这类形容词结论。

### §8 可改进处与独特优势

**必须回答**：每一项具体改什么、怎么验证、什么条件下优势会消失。

结构：
- 本项目每只：4 项可改进 + 3 项独特优势（可按实际调整数量）
- 组合层面：互补性矩阵（哪些风险对冲、哪些没有）
- 一句话总结

**三段式强制**：
- 可改进：现状 → 可改进方向 → **验证指标（下一期能查到的具体字段）**
- 优势：是什么 → 为什么别人没有 → **什么条件下会消失**

### §9 风险监测与下一期验证

**必须回答**：盯哪几个数、触发阈值多少、会改哪一句。

必含两段：
1. 监测指标表（指标 / 当前值 / 触发阈值 / 会改写哪一句）
2. 情景推演 —— "如果 X 发生，第 N 节的哪句话要改写"

**这一节是报告能否被复用的关键。** 没有它，下一期只能从头再来。

## 四、五张图的规范

| 图 | 内容 | 必须承载的信息 |
|---|---|---|
| 图 1 | 样本构造漏斗 | 候选池全貌、纳入/排除、排除理由落点 |
| 图 2 | 口径翻转斜线图 | 每个口径下的名次、连线交叉、极差 |
| 图 3 | 资产质量矩阵（热力） | 每维名次 + 原值，颜色深浅可读 |
| 图 4 | 定位散点 | 二维位置、象限、气泡=规模 |
| 图 5 | 商业模式两轴 | 赚钱能力 × 分派自给度 |

技术要求：
- 宽 940px，高按内容 560—650
- 字体 `Noto Sans SC, PingFang SC, Microsoft YaHei`
- 本项目统一用 `#c0392b`，其他用 `#2c5f8a`
- 每张图自带脚注（口径与来源），脱离正文也能读
- 图注格式：单独一行 `图 N　标题`（行首为"图"字，便于字数工具统计）

## 五、禁止清单

| 禁止 | 理由 |
|---|---|
| 给商业模式打总分/评级 | 权重取决于投资人偏好，总分是伪精确 |
| 用 n<10 做分位表述 | 6 个样本算不出有意义的分位数 |
| 报 p 值、说"显著" | 无推断能力 |
| 只取一套集中度披露 | 选择性引用 |
| 用"排序不一致"代替相关性检验 | 会被一个 r 值推翻 |
| 正文出现 FLOW 编号、状态码 | 读者看的是结论，不是流程 |
| "综合来看""整体处于中游" | 没有坐标与口径，等于没说 |
| 图作为单独附件 | 读者不会自己去拼 |

## 六、文风

- 短段落，每段一个判断，判断句加粗
- 数字后面跟解释，不只列数
- 每个结论给"但是"——条件式判断优于绝对判断
- 引用他人/前版结论时，直接说"上一版认为 X，本次核到 Y，因此改为 Z"
