# 公募 REITs 横向基准（peer benchmarking）

本 skill 是一个 flow（可执行分析流程）。

**执行方式**：阅读同目录下的 `FLOW.md`，按 `#1 → #11` 顺序执行。`#5` 产出的 `panel.csv` 是后续所有计算的唯一数据源，**任何后续步骤不得回头重读 PDF、重算单位、重定期间**。

**运行前检查**：
1. `METADATA.md` 的 `inputs` 前四项必须由用户确认：`project_funds`、`peer_universe`、`as_of`、`asset_type`。其余项可留空走默认。
2. `peer_universe` 若用户只给了"仓储物流""产业园"这类标签而没给代码清单，**必须自己全量枚举后回报候选池，不得凭印象列几只**。
3. `data_requirements` 中标 `criticality: blocker` 的条目（可供分配金额、经营活动现金流净额、期末可租面积、期末出租率）缺任一项，该标的**不进入排名**，只能进"样本外说明"。

**输出位置**：`outputs/case_XX_<slug>/`，交付 7 项：报告 md ＋ 自包含 html ＋ 5 张图 ＋ 4 个 csv ＋ 3 个可复跑脚本，清单见 FLOW `#11`。

## 这个 skill 回答什么

**不是"谁最好"，是"在什么口径下谁更好、这个结论有多稳、本项目该改什么"。**

三件事必须同时成立，报告才算完成：

1. **为什么是这几只** —— 候选池怎么枚举的、每只为什么纳入或排除、把边界动一动会改哪一句结论。**这一步做不实，后面所有排名都是自娱自乐。**
2. **本项目在什么位置** —— 收益率（三口径）、资产质量（四维）、定价（残差）三个坐标，每个都带排名与稳定性。
3. **商业模式差在哪、该改什么** —— 四问框架（钱从哪来 / 谁在管 / 风险谁担 / 增长靠什么）拆开，给出条件式优劣与本项目的具体可改进项，**不给总分**。

## 三条硬约束

- **样本必须可复现。** 「全样本」这三个字必须有清单支撑：候选池由基金全量清单枚举得出，纳入排除逐条写理由，被排除但影响结论的做边界检验。**没有清单的"全样本"是本 skill 最不能容忍的错误。**
- **单一排名不出结论。** 收益率至少三个口径（披露分派率 / 现金分派率 / 单位面积经营现金流），并计算**排名极差**；极差 ≥2 位时，任何"排第几"的句子都必须带口径标签。
- **商业模式不给总分。** 可以给适用条件与代价，可以给"要现金流稳定性选谁、要票息选谁"，但不给 1—10 分、不给评级。**给总分等于先验地定了权重，而权重取决于投资人要什么。**

- `report_peer_benchmarking_<year>.md` —— 正文（中文 ≥15,000 字符，口径见 `tools/count_report_words.py`）
- `report_peer_benchmarking_<year>.html` —— **自包含单文件，图内联为 SVG**，双击即读、离线可看

**图必须嵌在报告里，不能作为单独附件交付。** Markdown 版在 GitHub 上走相对路径渲染；HTML 版内联，两版同源。

## 最常踩的三个坑

1. **把"排序不一致"当成"两件事无关"。** 先算相关系数：`r > 0.7` 时只能谈残差，不能谈脱钩。实测：市值/㎡ 与 CFO/㎡ 的 r = 0.848，直接说"市场买位置不买坪效"会被一个数字推翻。
2. **一只标的只取一个集中度。** 盐田港同一份年报给出 36%（面积、一户）、58.12%（两户 >10%）、74.86%（前五）——**差两倍以上，取最有利于结论的那套就是选择性引用。** 必须"口径 + 户数"双标注，多套全列。
3. **季报与年报结论方向相反时只信一个。** 深国际季报前五 71.32%/最大 25.12%（看似市场化集中），年报 §4.4.2 披露同集团两子公司合计 36.75% + 关联方 18.47%——**实际 55.22% 依赖同一/自家集团**。交叉核对，冲突时以年报为准并写明。
